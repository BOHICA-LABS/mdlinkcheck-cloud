### BLOCKING-4 — `check-ec-injectivity.py`: "no Description column" skip suppresses at least 9 genuine SCENARIO-MISMATCH findings

| Field | Value |

| Severity | **blocking** |
| Category | coverage / oracle-blindness |

for i, cell in enumerate(cells):
    if "description" in cell.strip().lower():

...
if current_desc_col is None or current_desc_col >= len(cells):

| 175 | `Link` | (URL — legitimately non-comparable) |
| **199** | **`Source MD Content`** | **comparable scenario prose** |
| **234** | **`Input`** | **comparable scenario prose** |

The last two contain real scenario descriptions, not filenames. Adding just those two header

turn the checker RED with ~9 findings — per the PR's own framing that is the correct outcome and
routes to the content workstream; do **not** resolve it by narrowing the oracle further.

### BLOCKING-5 — `check-adr-consistency.py`: Pattern 1 table branch is blind to uppercase and annotated Reason cells, and its column index can be hijacked

| Field | Value |
|---|---|
| Severity | **blocking** |
| Category | coverage / oracle-blindness |
| File | `scripts/spec-lint/check-adr-consistency.py:300-343` |

The positional predicate correctly kills the cycle-1 false positives, but the table branch's
simple-value guard is narrower than the corpus it must police:

```python
m_simple = re.fullmatch(r"`?([a-z][a-z0-9-]{2,})`?", reason_cell.strip())
```

Three demonstrated holes (all reproduced against the shipped checker, all return
`Check passed ... 0 non-conforming`):

**1. Uppercase codes in a Reason column are invisible.** The character class is `[a-z]` only:
```
| TV | EC | Verdict | Reason |
|----|----|---------|--------|
| TV-001 | EC-001 | broken | `E-IO-002` |
| TV-002 | EC-002 | broken | `Retry-After` |
```
→ 0 violations. This directly contradicts the PR body's own change summary, which states
Pattern 1 is "backtick-quoted uppercase codes (catches `` `E-IO-002` ``)", and contradicts the
docstring the fix commit left in place at lines 185-187:
> `E-CLI-001 and E-IO-002 do NOT match this pattern because they have letters between the prefix and the numeric suffix`
That comment justifies keeping `E-IO-002` as a reason-code candidate, but after this commit
nothing can reach it in a table cell.

**2. A Reason cell with any annotation is skipped entirely:**
```
| TV-001 | EC-001 | broken | `phantom-gamma` (per D-018) |
```
→ 0 violations. `fullmatch` requires the cell to be a bare token.

**3. The Reason column index is hijacked by any data cell equal to `reason`.** The header scan
at lines 300-309 runs on *every* non-separator table row, not just header rows:
```
| TV | EC | Notes | Verdict | Reason |
|----|----|-------|---------|--------|
| TV-001 | EC-001 | reason | broken | `phantom-alpha` |
| TV-002 | EC-002 | ok     | broken | `phantom-beta`  |
```
→ 0 violations. Row TV-001 is misclassified as a header (so it is skipped) *and* it repoints
`current_reason_col_p1` from index 4 to index 2, so TV-002 is then scanned at the `Notes` column
and `phantom-beta` is never seen. Every subsequent row in the table is scanned at the wrong index.

**Corroborating evidence that this is an unnoticed regression, not a deliberate narrowing:** the
PR body's baseline table lists the four adr-consistency violations as
`(E-CLI-001, malformed-fragment, syntax-valid, E-IO-002)`. The actual output is:

```
BC-2.03.002.md:82  verdict reason code 'case-insensitive'
BC-2.11.004.md:61  taxonomy reference 'E-CLI-001'
test-vectors.md:221 verdict reason code 'syntax-valid'
test-vectors.md:432 verdict reason code 'malformed-fragment'
```

`E-IO-002` is **not** detected (it was, at `BC-2.01.009.md:52`, before this commit), and
`case-insensitive` is detected but not recorded. The author believes E-IO-002 coverage survived;
it did not. Selftest 5g covers only the lowercase bare-token happy path, which is why nothing
caught this.

*(For the record: I judge the pre-fix `E-IO-002` hit at `BC-2.01.009.md:52` — "an `E-IO-002`
error is recorded" — to have been a genuine false positive, since `E-IO-002` is a spec-defined
error-class ID also used in `interface-definitions.md:237`. Dropping that specific hit is fine.
What is not fine is that the *capability* to flag an uppercase phantom code sitting in a Reason
column was removed silently, and the baseline of record now misstates what the oracle found.)*

**Suggestion:**
- Broaden the simple-value guard to `[A-Za-z]` and allow a trailing annotation, e.g. match a
  leading bare/backticked token and ignore the remainder, rather than `fullmatch` on the cell.
- Gate header detection on an actual header row — require that the following line is a table
  separator row (`slp.is_table_separator_row`) before accepting a `Reason` cell as a header.
- Add negative selftests for all three shapes above (uppercase code, annotated cell, `reason`
  appearing as a data value), and correct the stale docstring at lines 185-187 plus the PR
  body's Pattern 1 description and baseline table.

## WARNING FINDINGS

### WARNING-1 — ADVISORY-6 best-match loop is inert and is an unproven sensitivity reduction

`scripts/spec-lint/check-ec-injectivity.py:396-409`. The loop selects, for each BC citation, the
TV row with the **highest** Jaccard score. Replacing the loop body with a no-op (falling back to
`tv_occs[0]`) changes the live result not at all — still `0 divergent, 0 require adjudication` —
so it is currently load-bearing for nothing. Structurally it can only ever move a comparison from
DIVERGENT toward PASS, i.e. it monotonically reduces oracle sensitivity, and no selftest proves
it necessary. The EI-4 comment even concedes "ADVISORY-6 best-match might still pick section A's
match". Recommend removing it, or if a real multi-section case motivates it, adding a selftest
that fails when it is disabled.

### WARNING-2 — TV verdict extraction silently yields `""` for 39 of 67 comparable rows

`scripts/spec-lint/check-ec-injectivity.py:220-227`. The right-to-left scan is anchored:
```python
re.match(r'^(alive|broken|indeterminate|clean|dead|valid)\b', cell_stripped, re.IGNORECASE)
```
The corpus writes verdicts parenthesized — `| ... | 0 | (clean) | Recursive traversal |` — so the
`^` anchor never matches and `verdict_raw` stays `""`. Measured: 39 of 67 comparable rows (58%)
now carry an empty verdict, which makes the BC-vs-TV verdict-collision arm skip them. This
produces no output change today only because BC edge-case tables are 2-column (`| EC | Description |`)
and so the BC side is empty anyway — the arm was already inert for an unrelated reason. Still,
the safety margin is gone and the approach is inconsistent with the schema-aware Description
handling in the same function. Suggestion: locate the `Verdict` / `Expected Verdict` column from
the header the same way Description is located, and strip surrounding `(` `)` and backticks.

### WARNING-3 — unrecognized TV section headers do not reset `current_desc_col`

`scripts/spec-lint/check-ec-injectivity.py:186-198`. Header rows are only recognized when
`cells[0] ∈ {TV, TV ID, TV-ID}` **and** `cells[1] ∈ {EC, EC ID, EC-ID}`. A section header that
fails that test falls through to the data-row branch and `continue`s **without clearing the
previous section's Description index**, so a stale column index leaks across a schema boundary.
Reproduced:

```
| TV | EC | Description | Exit | Verdict |      <- sets desc_col = 2
...
| Vector ID | Source MD | Exit | Verdict |      <- NOT recognized; desc_col stays 2
| TV-002 | EC-002 | a.md | 1 | broken |         <- compared as description "a.md"
```
→ `1 EC citations compared (0 non-comparable TV rows skipped)`, comparing BC
`'TLS handshake certificate chain expiry'` against TV `'a.md'`, and reporting zero skips.

`test-vectors.md:49` (`| Vector ID | Source MD | ... |`) is exactly this shape. It happens to be
the first table today, so nothing leaks in the live corpus — this is latent, not active.
Suggestion: reset `current_desc_col = None` on any table row that is neither a recognized header
nor a `TV-xxx` data row, and count such rows so the coverage line stays honest.
