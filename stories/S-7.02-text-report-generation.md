# S-7.02: Text Report Generation — `reporter::format_text` + `format_summary` + stdout/stderr separation

> **One-per-file:** This story is `S-7.02` in EPIC-07 — Output, Reporting, and Exit Codes (`E-7`).
> Implements the text-format half of the pure-core `reporter.rs` module:
> `reporter::format_text(findings, opts)` (per-finding lines to stdout),
> `reporter::format_summary(findings)` (summary to stderr), and the mandatory sort stage
> (ADR-005). Also wires `main.rs` to route reporter output to the correct file handles
> (stdout vs stderr separation, BC-2.12.005). Color control via `ReportOpts.color_mode`
> (populated by `cli.rs` from NO_COLOR/CLICOLOR/CLICOLOR_FORCE env vars).
> VP-011 proptest (P1, DI-001) verifies sort determinism.

## Narrative

- **As a** developer or CI engineer reading `mdlinkcheck` output
- **I want to** see each broken/indeterminate finding on its own line with file:line info, followed
  by a consistent summary on stderr, with color support controlled by environment variables
- **So that** I can pipe stdout through grep/wc without stderr contamination, script against
  the exit code, and get clear visual feedback in a terminal

### AC-001 (traces to BC-2.12.001 postcondition 1)
`reporter::format_text(findings, opts)` emits exactly one output line per finding with verdict
`broken` or `indeterminate`. Findings with verdict `clean` produce no output line.
- **Test:** `test_BC_2_12_001_one_line_per_non_clean_finding()`

### AC-002 (traces to BC-2.12.001 postcondition 2)
Each broken finding line has the exact format `<file>:<line>: <link_target> — <reason>`
where `<file>` is the CWD-relative NFC-normalized forward-slash path, `<line>` is the
1-based line number, `<link_target>` is the raw link destination string, and `<reason>`
is a closed-taxonomy reason code from `error-taxonomy.md`.
- **Test:** `test_BC_2_12_001_broken_line_format()`

### AC-003 (traces to BC-2.12.001 postcondition 3)
Each indeterminate finding line has the format
`<file>:<line>: <link_target> — [indeterminate] <reason>`.
The `[indeterminate]` prefix is literal and mandatory.
- **Test:** `test_BC_2_12_001_indeterminate_line_format()`

### AC-004 (traces to BC-2.12.001 postcondition 4)
When all findings have verdict `clean`, `format_text()` returns an empty string (zero output lines).
This property is verified by acceptance corpus integration tests; no dedicated VP exists.
- **Test:** `test_BC_2_12_001_clean_links_produce_no_output()`

### AC-005 (traces to BC-2.12.001 postcondition 5 and invariant 1)
Findings are sorted by `(NFC-normalized file path ascending, line ascending, column ascending,
link_target ascending)` before output. Two calls to `format_text()` with the same findings in
any input order produce byte-identical output (DI-001, ADR-005). VP-011 proptest covers this.
- **Test:** `test_BC_2_12_001_sort_deterministic_order()` (also exercised by VP-011)

### AC-006 (traces to BC-2.12.001 invariant 3)
`<file>` in output is CWD-relative, NFC-normalized (Unicode Normalization Form C), and uses
forward-slash (`/`) separators on all platforms including Windows.
- **Test:** `test_BC_2_12_001_file_path_nfc_forward_slash()`

### AC-007 (traces to BC-2.12.001 invariant 4)
Two runs of `mdlinkcheck` with byte-identical inputs produce byte-identical stdout
(NFR-003 byte-idempotent output). Verified by VP-011 proptest on the sort stage.
- **Test:** `test_BC_2_12_001_byte_identical_runs()`

### AC-008 (traces to BC-2.12.002 postcondition 1)
When `opts.color_mode` is `ColorMode::Auto` AND stdout is a TTY AND `NO_COLOR` is not set AND
`CLICOLOR` is not `"0"`, `format_text()` applies ANSI escape codes: broken findings in red,
indeterminate findings in yellow, file path component in bold.
- **Test:** `test_BC_2_12_002_color_applied_on_tty()`

### AC-009 (traces to BC-2.12.002 postcondition 2)
When `opts.color_mode` is `ColorMode::Never` (set by `cli.rs` when stdout is non-TTY and
`CLICOLOR_FORCE` is not `"1"`), `format_text()` produces no ANSI escape codes.
- **Test:** `test_BC_2_12_002_no_color_on_non_tty()`

### AC-010 (traces to BC-2.12.002 postcondition 3)
When `NO_COLOR` is set to any value (including empty string), `cli.rs` sets
`opts.color_mode = ColorMode::Never` and `format_text()` produces no ANSI codes.
- **Test:** `test_BC_2_12_002_no_color_env_suppresses_ansi()`

### AC-011 (traces to BC-2.12.002 postcondition 4)
When `CLICOLOR=0`, `cli.rs` sets `opts.color_mode = ColorMode::Never` and
`format_text()` produces no ANSI codes.
- **Test:** `test_BC_2_12_002_clicolor_0_suppresses_ansi()`

### AC-012 (traces to BC-2.12.002 postcondition 5)
When `CLICOLOR_FORCE=1`, `cli.rs` sets `opts.color_mode = ColorMode::Always` and
`format_text()` applies ANSI codes regardless of TTY status (e.g., when stdout is a pipe).
- **Test:** `test_BC_2_12_002_clicolor_force_enables_color_on_pipe()`

### AC-013 (traces to BC-2.12.002 invariant 1)
The same findings are reported in both color and no-color modes; only the ANSI escape
sequences differ. `format_text()` with `ColorMode::Never` and `ColorMode::Always` on the
same input produce the same finding text after stripping ANSI codes.
- **Test:** `test_BC_2_12_002_color_is_cosmetic_only()`

### AC-014 (traces to BC-2.12.003 postcondition 1)
`reporter::format_summary(findings)` returns `"N broken link(s) in M file(s)."` when the
count of findings with verdict `broken` is N > 0, where M is the count of distinct
`finding.file` values among broken findings. Indeterminate findings are NOT counted in N.
- **Test:** `test_BC_2_12_003_summary_broken_count_and_file_count()`

### AC-015 (traces to BC-2.12.003 postcondition 2)
`reporter::format_summary(findings)` returns `"No broken links found."` when no finding has
verdict `broken`, regardless of whether indeterminate findings are present.
- **Test:** `test_BC_2_12_003_summary_no_broken_even_with_indeterminate()`

### AC-016 (traces to BC-2.12.003 invariant 1 and invariant 2)
`format_summary()` always returns a non-empty string. `"No broken links found."` is the
correct summary even when indeterminate findings exist. There is no condition under which
summary is suppressed (D-011: `--quiet` is an explicit non-goal).
- **Test:** `test_BC_2_12_003_summary_always_emitted()`

### AC-017 (traces to BC-2.12.005 postcondition 1 and postcondition 2)
Every line produced by `format_text()` (broken and indeterminate findings) is written
exclusively to stdout. No finding line appears on stderr.
- **Test:** `test_BC_2_12_005_findings_go_to_stdout_only()` (integration test capturing both streams)

### AC-018 (traces to BC-2.12.005 postcondition 3)
The string returned by `format_summary()` is written exclusively to stderr by `main.rs`.
It never appears on stdout.
- **Test:** `test_BC_2_12_005_summary_goes_to_stderr_only()` (integration test)

### AC-019 (traces to BC-2.12.005 postcondition 4)
When there are no broken or indeterminate findings, stdout is empty (zero bytes written
to stdout for findings). `format_text()` returns `""` for an all-clean or zero-finding input.
- **Test:** `test_BC_2_12_005_stdout_empty_when_no_findings()`

### AC-020 (traces to BC-2.12.005 invariant 1)
A caller can redirect `2>/dev/null` to obtain findings-only stdout, and can redirect
`>/dev/null` to obtain only the summary on stderr. The two streams are completely
independent and never contain each other's content.
- **Test:** `test_BC_2_12_005_streams_are_independent()` (integration test)

## Purity Classification

| Module | Classification | Justification |
|--------|---------------|---------------|
| `crates/mdlinkcheck-core/src/reporter.rs` | pure-core | Takes `&[Finding]` and `ReportOpts`, returns `String`; no I/O; serde_json is a pure serialization dep; ADR-001 |
| `crates/mdlinkcheck/src/cli.rs` | effectful-shell | Reads `NO_COLOR`, `CLICOLOR`, `CLICOLOR_FORCE`, `isatty()` to produce `ReportOpts.color_mode`; no other I/O in this story's scope |
| `crates/mdlinkcheck/src/main.rs` | effectful-shell | Calls `println!()` (stdout) for findings, `eprintln!()` (stderr) for summary; the only file that crosses the pure/effectful stream seam |

## Forbidden Dependencies

`reporter.rs` MUST NOT import from `cli`, `main`, `scanner`, `http_client`, `app`, `std::fs`,
`std::net`, or `std::io`. If any of these appear in `reporter.rs`'s dependency tree, the build
MUST fail (ADR-001). `reporter.rs` depends only on `types` and `serde_json`.

`cli.rs` (color env-var reading) MUST NOT import from `reporter`, `verdict`, `scanner`, or
`http_client`. `cli.rs` produces `CliArgs` (including `ReportOpts`) and returns them; it does
not call reporter.
