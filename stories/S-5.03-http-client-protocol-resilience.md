# S-5.03: `http_client` — HEAD/GET Protocol, Timeout, Rate-Limiting, Redirects, and Concurrency

> **One-per-file:** This story is `S-5.03` in EPIC-05 — External URL Checking (`E-5`).
> Implements the effectful `http_client.rs` module covering: the HEAD-then-GET fallback
> protocol (BC-2.10.001), the 10-second per-URL timeout (BC-2.10.003), the 429 rate-limit
> pause-and-resume with RFC 9110 Retry-After parsing (BC-2.10.004), redirect chain following
> with max-10 and HTTPS→HTTP downgrade detection (BC-2.10.007), and the dedicated 32-thread
> rayon pool with 4-per-host concurrency cap (BC-2.10.008).
>
> All verification is **test-sufficient** for this story's BCs (httpmock 0.8.3 integration
> tests). All BCs here are test-sufficient per VP-INDEX v1.7. **Depends on S-5.01
> (url_classifier types) and S-5.02 (http_verdict — classify_response API) being complete.**

## Narrative

- **As a** developer running `mdlinkcheck --online`
- **I want** the tool to check external URL liveness with a resilient HEAD-then-GET protocol,
  respect rate limits from servers, follow redirects up to 10 hops, and limit concurrency to
  32 global / 4 per-host without starving the file-scan rayon pool
- **So that** liveness checks are thorough, well-behaved toward servers, and complete in
  bounded time without false failures from transient conditions

### AC-001 (traces to BC-2.10.001 postcondition 2)
When `http_client` sends a HEAD request and the server responds with 2xx, the result
is liveness outcome `alive`. `http_verdict::classify_response` is called with the 2xx
status and `HttpAttempt::Head`, returning `Verdict::Clean`. No GET request is sent.
- **Test:** `test_BC_2_10_001_head_2xx_yields_alive_no_get()`

### AC-002 (traces to BC-2.10.001 postcondition 3 and invariant 1)
When HEAD returns a status in the GET-fallback trigger set `{400, 403, 404, 405, 501, 999}`
or a transport failure (connection reset, DNS-level error), `http_client` sends a GET
request to the same URL. GET is triggered on EXACTLY this set — not for all non-2xx.
- **Test:** `test_BC_2_10_001_head_fallback_trigger_set_sends_get()` (parameterized over all 6 trigger statuses)

### AC-003 (traces to BC-2.10.001 postconditions 4 and 5)
When HEAD triggers GET fallback and GET returns 200–299, the liveness outcome is `alive`.
When GET returns 404 or 410, the verdict is `broken(http-error)`. `http_verdict::classify_response`
is called with the GET status and `HttpAttempt::GetFallback`.
- **Test:** `test_BC_2_10_001_get_fallback_200_yields_alive()` and `test_BC_2_10_001_get_fallback_404_yields_broken()`

### AC-004 (traces to BC-2.10.001 postcondition 6)
When GET returns a 4xx status that is NOT 404 or 410 (e.g., 403, 429, other 4xx), or a
5xx status, the verdict is `indeterminate`. GET returning 400 is also indeterminate
(D-018 applies to GET results via `classify_response(400, HttpAttempt::GetFallback)`).
- **Test:** `test_BC_2_10_001_get_fallback_non_404_410_yields_indeterminate()`

### AC-005 (traces to BC-2.10.001 invariant 3)
Redirect hops count across HEAD and GET fallback combined. If HEAD follows 6 redirects
and then GET follows 5 more, the combined chain is 11 hops → `broken(too-many-redirects)`.
- **Test:** `test_BC_2_10_001_redirect_count_shared_across_head_and_get()`

### AC-006 (traces to BC-2.10.003 postcondition 2 and invariant 1)
If no response is received within 10 seconds (wall-clock from request start), the verdict
is `indeterminate(http-timeout)`. The timeout applies to the total per-URL budget, shared
by HEAD and any GET fallback.
- **Test:** `test_BC_2_10_003_timeout_10s_yields_http_timeout()` (httpmock with artificial delay)

### AC-007 (traces to BC-2.10.003 postcondition 3)
HEAD and GET share the 10-second budget. A HEAD that takes 6 seconds and a GET that takes
6 more seconds exceeds the budget and yields `indeterminate(http-timeout)` — not 10 seconds
per individual request.
- **Test:** `test_BC_2_10_003_head_plus_get_share_10s_budget()`

### AC-008 (traces to BC-2.10.003 invariant 2)
`http-timeout` is `indeterminate`, not `broken`. Timeout does not contribute to exit 1.
This is DI-010 enforcement (429, 5xx, and timeouts are never broken).
- **Test:** `test_BC_2_10_003_timeout_is_indeterminate_not_broken()`

### AC-009 (traces to BC-2.10.004 postconditions 1 and 2)
When a 429 response is received for a URL, that URL's liveness outcome is
`indeterminate(http-indeterminate)` and all pending requests to the same hostname are
paused immediately.
- **Test:** `test_BC_2_10_004_429_triggers_host_pause()`

### AC-010 (traces to BC-2.10.004 postcondition 3)
The pause duration is derived from `Retry-After` per RFC 9110 §10.2.3:
- Delta-seconds (non-negative integer): pause that many seconds.
- HTTP-date: pause `max(0, date − now)` seconds.
- Absent, unparseable, negative, or non-numeric-non-date: 60 seconds default AND a
  `[warn]` diagnostic with the raw header value emitted to stderr.
- **Test:** `test_BC_2_10_004_retry_after_delta_seconds()`, `test_BC_2_10_004_retry_after_http_date()`, `test_BC_2_10_004_retry_after_missing_defaults_60s_with_warn()`

### AC-011 (traces to BC-2.10.004 postcondition 6 and invariant 4)
The honored pause is clamped to `min(computed, 120s)`. A `Retry-After` value exceeding 120s
(e.g., 86400) is honored at 120s and a `[warn]` diagnostic is emitted to stderr. This bound
prevents server-controlled infinite blocking.
- **Test:** `test_BC_2_10_004_retry_after_exceeds_clamp_honored_at_120s_with_warn()`

### AC-012 (traces to BC-2.10.004 invariant 2 and 3)
The pause is per-hostname. Pausing host A does not pause host B. After the pause elapses,
requests to host A resume; their verdicts are independent (not all automatically
indeterminate from the pause).
- **Test:** `test_BC_2_10_004_pause_is_per_host_not_global()`

### AC-013 (traces to BC-2.10.007 postcondition 1)
HTTP redirects (301, 302, 307, 308) are followed automatically. After up to 10 redirects,
the final response status is passed to `classify_response` for verdict determination.
- **Test:** `test_BC_2_10_007_follows_up_to_10_redirects()`

### AC-014 (traces to BC-2.10.007 postcondition 2 and invariant 1)
If the redirect chain exceeds 10 hops, the verdict is `broken(too-many-redirects)`. The
10-hop limit is absolute and cannot be configured.
- **Test:** `test_BC_2_10_007_11_redirects_yields_too_many_redirects()`

### AC-015 (traces to BC-2.10.007 postcondition 3 and invariant 2)
If the redirect chain contains an HTTPS→HTTP downgrade (i.e., an HTTPS URL redirects to
an HTTP URL), the verdict is `indeterminate(http-indeterminate)` with `sub_reason:
https-downgrade`. The downgraded request is NOT followed.
- **Test:** `test_BC_2_10_007_https_to_http_downgrade_yields_indeterminate()`

### AC-016 (traces to BC-2.10.007 invariant 3)
If a redirect target URL is the same as a URL already in the chain (loop detection), the
chain is broken immediately with verdict `broken(too-many-redirects)`.
- **Test:** `test_BC_2_10_007_redirect_loop_yields_too_many_redirects()`

### AC-017 (traces to BC-2.10.008 postconditions 1 and 2)
At most 32 HTTP requests are in-flight simultaneously across all hosts, and at most 4
requests are in-flight simultaneously to any single hostname. Observable via httpmock
concurrent-connection counting.
- **Test:** `test_BC_2_10_008_global_limit_32_per_host_limit_4()` (mock server counts concurrent open connections)

### AC-018 (traces to BC-2.10.008 invariant 3)
HTTP dispatch uses a **dedicated rayon thread pool of fixed size 32**, separate from the
global/file-scan rayon pool. File-scan parallelism (Pass 1/Pass 2) is not starved by
blocked HTTP threads.
- **Test:** `test_BC_2_10_008_dedicated_pool_does_not_share_with_scan_pool()`

### AC-019 (traces to BC-2.10.008 postcondition 3)
When a concurrency slot frees (a request completes), the next queued request begins
immediately without manual waking.
- **Test:** `test_BC_2_10_008_next_queued_starts_when_slot_frees()`

## Architecture Mapping

| Component | Module | Pure/Effectful |
|-----------|--------|---------------|
| HTTP request dispatch (ureq HEAD/GET) | `crates/mdlinkcheck/src/http_client.rs` | effectful-shell |
| Per-host concurrency semaphores | `crates/mdlinkcheck/src/http_client.rs` | effectful-shell |
| 429 pause state (per-host) | `crates/mdlinkcheck/src/http_client.rs` | effectful-shell |
| Redirect chain following | `crates/mdlinkcheck/src/http_client.rs` (ureq built-in + override) | effectful-shell |
| Dedicated rayon HTTP pool | `crates/mdlinkcheck/src/http_client.rs` | effectful-shell |
| Response verdict classification | `crates/mdlinkcheck-core/src/http_verdict.rs` | pure-core (secondary) |

**Pure/effectful seam:** `http_client` (this story) is the effectful shell of SS-10. It
issues network requests and calls `http_verdict::classify_response(status, attempt)` to
classify responses. All state — the memo table, per-host semaphores, 429 pause flags — lives
in `http_client`. `http_verdict` receives only `(u16, HttpAttempt)` and returns a `Verdict`
with no side effects. The seam is enforced by ADR-001.

## Edge Cases

> **D-246 NOTICE:** EC-085 and EC-086 citations in BC-2.10.001 are NOT authoritative
> (D-246 / ec-injectivity-adjudication.md). The BC documents HEAD-succeeds-200 and
> both-HEAD-and-GET-return-404; the registry entries describe unrelated redirect scenarios.
> Scenario text from BC-2.10.001 is authoritative.

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-085 (id not authoritative — D-246) | HEAD returns 200 (success) | `alive` → `Verdict::Clean`; no GET request sent |
| EC-086 (id not authoritative — D-246) | HEAD returns 404; GET also returns 404 | `broken(http-error)` after full HEAD→GET fallback |
| EC-080 | HEAD returns 403 (Forbidden/bot-blocking) | GET fallback triggered (403 ∈ trigger set); GET verdict determines outcome |
| EC-199 | 429 with `Retry-After: 30` | Host paused 30s; all pending requests for that host wait |
| EC-087b | 429 with no Retry-After header | Host paused 60s (default); `[warn]` emitted |
| EC-087c | 429 when all URLs are to the same host | All pending requests wait; unaffected by other hosts |
| EC-087d | 429 with HTTP-date `Retry-After` (future timestamp) | Pause `max(0, date − now)` seconds, clamped to 120s |
| EC-087e | 429 with malformed `Retry-After: abc` | 60s default pause; `[warn]` with raw header value |
| EC-087f | 429 with `Retry-After: 86400` | Clamped at 120s; `[warn]` diagnostic |
| EC-203 | Redirect chain of 11 hops | `broken(too-many-redirects)` |
| EC-204 | HTTP → HTTPS upgrade in redirect chain | Followed (HTTP→HTTPS upgrade is allowed; only HTTPS→HTTP downgrade is blocked) |
| EC-087g | HTTPS → HTTP downgrade in redirect chain | `indeterminate(http-indeterminate; sub_reason: https-downgrade)`; downgraded request NOT sent |
| EC-088b | 100 URLs to same host | Mock server observes ≤ 4 simultaneous connections at any instant |
| EC-088c | 100 URLs to 100 different hosts | Each mock server observes ≤ 1 connection; global total ≤ 32 |

## Purity Classification

| Module | Classification | Justification |
|--------|---------------|---------------|
| `crates/mdlinkcheck/src/http_client.rs` | effectful-shell | Issues ureq HTTP requests (network I/O), manages rayon thread pool, holds per-host Arc<Mutex<>> concurrency state. ADR-001 effectful boundary. |
| `crates/mdlinkcheck-core/src/http_verdict.rs` | pure-core (secondary) | Called by http_client to classify responses; returns Verdict with no side effects. |

**Forbidden Dependencies (build-time enforcement):**
- `http_client.rs` MUST NOT import `tokio`, `reqwest`, `async-std`, or any async runtime.
  ureq 3.3.0 is sync; all HTTP calls are blocking in the dedicated rayon pool (ADR-004).
- `http_client.rs` MUST NOT import any module from `mdlinkcheck-core` that is Kani-targetable
  as a direct dependency other than `http_verdict` and `types`. url_classifier results flow
  in as already-classified `UrlKind` values; http_client does not re-classify URLs.
