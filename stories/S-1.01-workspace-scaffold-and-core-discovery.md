# S-1.01: Workspace Scaffold, Shared Types, and Default-CWD File Discovery

> **One-per-file:** This story is `S-1.01` in EPIC-01 — File Discovery and Scanning Pipeline (`E-1`).
> Implements the Cargo workspace structure, all shared types in `mdlinkcheck-core`, and the
> core recursive `.md` discovery logic in `scanner.rs` using `ignore::WalkBuilder`.

## Narrative

- **As a** developer or CI system using `mdlinkcheck`
- **I want to** run `mdlinkcheck` with no arguments in a project directory
- **So that** every `.md` file in the directory tree is automatically discovered, `.gitignore`-excluded files are skipped, dot-directories are never entered, and only exact-`.md`-extension files are scanned

## Behavioral Contracts

| BC | Title | Priority |
|----|-------|----------|
| BC-2.01.001 | Recursive `.md` Discovery with Default Scan Root | P0 |
| BC-2.01.003 | `.gitignore` and `.ignore` Exclusion During Traversal | P0 |
| BC-2.01.004 | Dot-Directory Skip (Unconditional) and Directory-Symlink Non-Following | P0 |
| BC-2.01.005 | Extension Matching — `.md` Only, Case-Sensitive | P0 |

## Acceptance Criteria

> **Verification Properties:** VP-016 (`.gitignore` exclusion — files matching `.gitignore`
> patterns are never in the scan set) and VP-017 (scan termination for any directory tree
> including symlink cycles) are referenced in frontmatter per VP-INDEX v1.7. The remaining
> BCs in this story are test-sufficient per VP-INDEX v1.7 (covered by acceptance corpus).

### AC-001 (traces to BC-2.01.001 postcondition 1)
When `mdlinkcheck` is invoked with no PATH arguments in a readable directory, every file with
the exact lowercase extension `.md` reachable from CWD (subject to `.gitignore`, dot-dir, and
extension rules) is included in the scan set exactly once.
- **Test:** `test_BC_2_01_001_default_cwd_scan_includes_all_md_files()`

### AC-002 (traces to BC-2.01.001 postcondition 2)
No `.md` file is included more than once in the scan set even if multiple traversal paths could
reach the same file (e.g., via nested directories).
- **Test:** `test_BC_2_01_001_no_duplicate_in_scan_set()`

### AC-003 (traces to BC-2.01.001 postcondition 3)
Traversal terminates for any finite directory tree; bounded depth and no-symlink-cycle
guarantees (via VP-017) ensure the scan always completes.
- **Test:** `test_BC_2_01_001_scan_terminates_for_finite_tree()`

### AC-004 (traces to BC-2.01.003 postcondition 1)
Every file that matches a pattern in any applicable `.gitignore` or `.ignore` file is excluded
from the scan set. `node_modules/foo.md` with `node_modules/` in `.gitignore` produces zero
findings from that path.
- **Test:** `test_BC_2_01_003_gitignore_excludes_from_scan_set()`

### AC-005 (traces to BC-2.01.003 invariant 1)
A file excluded by `.gitignore` is NOT scanned as a link source; no links from that file are
checked or reported.
- **Test:** `test_BC_2_01_003_gitignored_file_not_scanned_as_source()`

### AC-006 (traces to BC-2.01.003 invariant 2)
A file excluded by `.gitignore` that is referenced as an anchor link target from an in-scan-set
file still has its anchor table built (DI-006 case 2). Pass 1.5 handles this via AnchorIndex
membership check. The gitignored file itself is not added to the scan set.
- **Test:** `test_BC_2_01_003_gitignored_file_anchor_table_built_as_target()`

### AC-007 (traces to BC-2.01.004 postcondition 1)
Directories whose names begin with `.` (e.g., `.github/`, `.git/`, `.vitepress/`) are
unconditionally skipped during traversal; no `.md` files inside them are added to the scan set.
- **Test:** `test_BC_2_01_004_dot_directories_unconditionally_skipped()`

### AC-008 (traces to BC-2.01.004 invariant 1)
There is no flag that overrides dot-directory skipping (D-011 — `--hidden` is an explicit
non-goal). All dot-directories are always excluded regardless of invocation flags.
- **Test:** `test_BC_2_01_004_no_override_flag_for_dot_dir_skip()`

### AC-009 (traces to BC-2.01.004 postcondition 2)
Directory symlinks are never followed during traversal (DI-009). Traversal terminates normally
even when a directory symlink cycle is present (e.g., `a/b -> a`).
- **Test:** `test_BC_2_01_004_directory_symlinks_not_followed()`

### AC-010 (traces to BC-2.01.004 invariant 3)
A `.md` file inside a skipped dot-directory that is referenced as a cross-file anchor target
from an in-scan-set file still has its anchor table built (DI-006 case 3). Pass 1.5 identifies
it via AnchorIndex membership absence and builds the table. The dot-dir file is NOT added to
the scan set as a source.
- **Test:** `test_BC_2_01_004_dot_dir_md_file_anchor_table_built_as_target()`

### AC-011 (traces to BC-2.01.005 postcondition 1)
Files with the exact extension `.md` (lowercase, case-sensitive byte comparison of the final
suffix) discovered via directory traversal are included in the scan set.
- **Test:** `test_BC_2_01_005_exact_md_extension_included()`

### AC-012 (traces to BC-2.01.005 postcondition 2)
Files with extensions `.MD`, `.Md`, `.markdown`, `.mdx`, `.mdown`, `.mkd`, `.txt`, `.html`,
and all other non-exact-`.md` extensions are excluded from the scan set when discovered via
directory traversal (D-012).
- **Test:** `test_BC_2_01_005_non_md_extensions_excluded()`

### AC-013 (traces to BC-2.01.005 invariant 1)
Extension matching uses a case-sensitive byte comparison of the exact string `.md`; `.MD`
and `.Md` are NOT matched because byte comparison is case-sensitive.
- **Test:** `test_BC_2_01_005_case_sensitive_byte_match()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | CWD has no `.md` files at any depth | Scan set is empty; no crash; exit 0 with "No markdown files found." message (exit message behavior in S-1.02) |
| EC-002 | `node_modules/**/*.md` (5000 files); `node_modules/` in `.gitignore` | All 5000 files excluded; no performance blowout; exit 0 if no findings elsewhere |
| EC-003 | `.github/PULL_REQUEST_TEMPLATE.md` with a broken link | File is in a dot-directory; unconditionally skipped; no findings reported from it |
| EC-004 | `.git/` directory contains files ending in `.md` | Dot-directory; unconditionally skipped; `.md` files inside are never in scan set as sources |
| EC-005 | `README.MD` (uppercase extension) in tree | Case-sensitive extension filter rejects `.MD`; file excluded from scan set |
| EC-006a | `notes.markdown` in tree | Extension `.markdown` rejected (D-012 non-goal); file excluded |
| EC-006b | `notes.mdx` in tree | Extension `.mdx` rejected (D-012 non-goal); file excluded |
| EC-008 | Directory symlink creating cycle `a/b -> a` | Dir symlinks never followed; traversal terminates normally (DI-009 / VP-017) |
| EC-009 | Symlink `docs -> ../shared-docs` (directory symlink) | Not followed; files under `../shared-docs` not discovered unless separately specified |

## Architecture Compliance Rules (MANDATORY)

| Rule | Source | Enforcement |
|------|--------|-------------|
| `mdlinkcheck-core` MUST NOT contain any `std::fs`, `std::net`, `std::io::stdout`, `std::time::Instant::now`, or random-number imports | ADR-001 | `cargo deny` rule; code review; Kani harnesses fail to compile if I/O imported |
| `scanner.rs` MUST use `ignore::WalkBuilder` for traversal (not manual `fs::read_dir` loop) | ADR-005 (rayon traversal), dependency-graph.md §mdlinkcheck binary | Compile check: only `ignore` crate calls `fs::read_dir` on walker's behalf |
| Dot-directory skip MUST be unconditional; no flag may override it | BC-2.01.004 invariant 1, D-011 | Test AC-008: no `--hidden` flag accepted; `clap` must not define it |
| Extension matching MUST be case-sensitive byte comparison of exact string `.md` | BC-2.01.005 invariant 1, D-012 | Test AC-013: `README.MD` and `notes.markdown` not in scan set |
| `WalkBuilder` MUST have `follow_links(false)` for directory symlinks | BC-2.01.004 postcondition 2, DI-009 | Test AC-009: dir symlink cycle does not loop |
| Workspace MUST use `resolver = "2"` and `msrv = "1.85"` | module-decomposition.md §Workspace Layout | `cargo check` with MSRV toolchain |
| `ParsedFile` MUST NOT carry a `dir_entries` field (moved to `DirIndex` per SR-016) | module-decomposition.md v1.2 changelog | Code review: `ParsedFile` struct definition |
