# S-6.02: `--allow` URL Prefix Exemption and Invalid-Glob Startup Gate

> EPIC-06 — Filter Application. One-per-file rule enforced.

## Narrative

- **As a** developer running `mdlinkcheck` in CI
- **I want to** exempt known-safe URL prefixes from external checks with `--allow`, and
  receive an immediate exit 2 if an `--ignore` glob is syntactically invalid
- **So that** internal tools and build servers are not flagged as broken links, partial
  matches cannot bypass the allowlist via host-suffix tricks, and misconfigured CI
  invocations fail fast before spending time on file traversal

## Acceptance Criteria

### AC-001 (traces to BC-2.11.002 postcondition 5)
Given `--allow https://example.com` and a URL `https://example.com/path` classified as
`external-http`, the URL is matched by the allow prefix and receives verdict `clean` — it
is not emitted in findings output.

**Test:** `test_BC_2_11_002_allow_prefix_exact_match_exempts_url()`

### AC-002 (traces to BC-2.11.002 postcondition 6)
A URL that does not match any `--allow` prefix proceeds with normal validation (offline
syntax check or online liveness check). No silent exemption occurs.

**Test:** `test_BC_2_11_002_non_matching_url_not_exempted()`

### AC-003 (traces to BC-2.11.002 invariant 1)
The component-boundary check ensures the character immediately after the allow prefix
in the URL must be `/`, `?`, `#`, or end-of-string. `--allow https://example.com` does
NOT exempt `https://example.com.evil.tld/path` because the character after the prefix
(`.`) fails this check, preventing host-suffix bypass.

**Test:** `test_BC_2_11_002_component_boundary_prevents_suffix_bypass()` (proptest VP-010)

**VP-010 note (own words):** `filter::allow_match` enforces a URL-component boundary
after any matching prefix: the character immediately following the prefix must be `/`,
`?`, `#`, or end-of-string. This prevents `--allow https://example.com` from matching
`https://example.com.evil.tld`. A naive `starts_with` is never used.

### AC-004 (traces to BC-2.11.002 postcondition 2 — normalized prefix match, Path A)
For well-formed URLs where WHATWG normalization succeeds, the normalized URL is
prefix-matched against each allow prefix, then the component-boundary check is applied
to the normalized URL. Two URLs that normalize to the same string both match the same
prefix.

**Test:** `test_BC_2_11_002_normalized_url_prefix_match()`

### AC-005 (traces to BC-2.11.002 postcondition 3 — raw-string fallback, Path B)
For malformed URLs where WHATWG normalization fails (e.g., `https://build_server/status`
— underscore in hostname is rejected by WHATWG), the raw URL string is prefix-matched
against each allow prefix with the identical component-boundary rule. The malformed
intranet URL `https://build_server/status` is exempted by
`--allow https://build_server`.

**Test:** `test_BC_2_11_002_malformed_url_raw_string_fallback()`

### AC-006 (traces to BC-2.11.002 invariant 2)
`--allow` is a literal URL prefix, not a glob. Wildcards have no special meaning.
`--allow https://example.com/*` is matched as the literal string `https://example.com/*`,
not as a pattern.

**Test:** `test_BC_2_11_002_allow_is_literal_not_glob()`

### AC-007 (traces to BC-2.11.002 invariant 3)
Multiple `--allow` flags are evaluated as logical OR: a URL matching ANY one of the
allow prefixes is exempt. `--allow https://a.com --allow https://b.com` exempts URLs
starting with either prefix (subject to the boundary check for each).

**Test:** `test_BC_2_11_002_multiple_allow_flags_ored()`

### AC-008 (traces to BC-2.11.002 postcondition 7)
`--allow` applies in both offline (default) and `--online` modes. An allowed URL is
exempt from both syntax validation and liveness checking regardless of mode.

**Test:** `test_BC_2_11_002_allow_applies_in_offline_and_online_modes()`

### AC-009 (traces to BC-2.11.004 postcondition 1)
An invalid `--ignore` glob — one that fails `globset::GlobBuilder::new(pattern).build()`
— causes the tool to exit with code 2 immediately. Exit 2 is a usage/configuration error
per the error taxonomy (ADR-007).

**Test:** `test_BC_2_11_004_invalid_glob_exits_2()`

**Edge case EC-207:** `--ignore '[abc'` (unclosed bracket) → exit 2; error on stderr;
no scanning.

### AC-010 (traces to BC-2.11.004 postcondition 2)
The stderr message for an invalid glob is exactly:
`error: invalid --ignore glob '<pattern>': <reason>`
where `<pattern>` is the offending pattern string and `<reason>` is the error description
from globset. The pattern and reason are both included.

**Test:** `test_BC_2_11_004_invalid_glob_stderr_message_format()`

### AC-011 (traces to BC-2.11.004 postcondition 3)
No file traversal occurs when an invalid glob is supplied. Glob validation runs at
startup before any call to the scanner or traversal loop.

**Test:** `test_BC_2_11_004_no_traversal_on_invalid_glob()`

### AC-012 (traces to BC-2.11.004 postcondition 5)
Stdout is empty when the tool exits with code 2 due to an invalid glob pattern. The
error output goes only to stderr.

**Test:** `test_BC_2_11_004_invalid_glob_stdout_empty()`

### AC-013 (traces to BC-2.11.004 invariant 1)
Glob validation happens at startup before any scanning. A valid first glob followed by
an invalid second glob (`--ignore 'valid/**' --ignore '[bad'`) exits 2 immediately;
the valid pattern is not applied because validation fails before traversal begins
(edge case EC-208).

**Test:** `test_BC_2_11_004_any_invalid_glob_fails_before_traversal()`

### AC-014 (traces to BC-2.11.004 invariant 3)
Exit code 2 is used for all configuration errors including invalid --ignore globs.
The `cli` module sets `config_error = true` and calls `verdict::exit_code(findings,
io_errors, config_error: true)` which returns 2 (INC-MAP-003 route:
cli → verdict::exit_code via config_error bool).

**Test:** `test_BC_2_11_004_exit_code_2_routes_through_verdict()`

## Architecture Compliance Rules (MANDATORY)

| Rule | Source | Enforcement |
|------|--------|-------------|
| `filter::allow_match` must be pure core (no I/O; uses only `url::Url::parse()` which is deterministic) | ADR-001 (pure-core/effectful-shell boundary) | `cargo check -p mdlinkcheck-core` must compile cleanly; any fs::*, net::*, or process::* call in filter.rs is a violation |
| `filter.rs` lives in `mdlinkcheck-core`, not `mdlinkcheck` | ADR-002 (workspace layout) | Physical file path enforced by Cargo workspace; incorrect placement causes compile errors |
| Two-path algorithm (D-019): Path A normalized + boundary check; Path B raw-string fallback + same boundary check | BC-2.11.002 description, ADR-007 (verdict model) | Both paths must enforce the boundary rule; test EC-build-server (Path B) and EC-162 (Path A bypass attempt) explicitly |
| Component boundary: next char after prefix must be `/`, `?`, `#`, or end-of-string — BOTH paths | BC-2.11.002 invariant 1 | VP-010 proptest passes (generated bypass_url with host suffix must NOT be allowed) |
| Glob validation in `cli.rs` runs at startup before any traversal (globset::GlobBuilder::new().build()) | BC-2.11.004 invariant 1, INC-MAP-003 | Integration test EC-207: assert no scan output + exit 2 + stderr message; no file traversal side effects |
| Invalid glob error route: cli sets config_error=true → passes to verdict::exit_code(findings, io_errors, config_error: bool) | module-decomposition.md v1.2 changelog (INC-MAP-003) | AC-014 test: confirm exit code 2 is produced via the verdict::exit_code route, not via process::exit(2) hardcoded in cli |
