# S-7.04: CLI Output Format Selection, `--help`, `--version`, and `main.rs` Full Routing

> **One-per-file:** This story is `S-7.04` in EPIC-07 — Output, Reporting, and Exit Codes (`E-7`).
> Wires the final output-selection layer: `cli.rs` parses `--format text|json` (exit 2 on any
> other value, before scanning begins); `cli.rs` also exposes `--help` and `--version` via clap
> (exit 0 without invoking `app::run()`). `main.rs` dispatches to `reporter::format_text()` or
> `reporter::format_json()` based on the parsed `OutputFormat` enum, calls
> `verdict::exit_code()`, and writes the process exit code.
> Both BCs are test-sufficient per VP-INDEX v1.7; no Kani or proptest VP required.

## Narrative

- **As a** developer or CI system using `mdlinkcheck`
- **I want to** choose between human-readable text and machine-parseable JSON output,
  and get help/version information without triggering a scan
- **So that** I can integrate `mdlinkcheck` into pipelines that consume structured output,
  probe tool availability in CI scripts without false exits, and receive an immediate
  error when an unsupported format is requested

## Acceptance Criteria

### AC-001 (traces to BC-2.12.004 postcondition 1)
`--format text` (explicit flag) produces the same text output as running with no `--format`
flag. The `OutputFormat::Text` variant is selected in both cases.
- **Test:** `test_BC_2_12_004_format_text_alias_produces_text_output()`

### AC-002 (traces to BC-2.12.004 postcondition 1)
No `--format` flag on the command line selects text output (the default). Behavior is
identical to `--format text`.
- **Test:** `test_BC_2_12_004_no_format_flag_defaults_to_text()`

### AC-003 (traces to BC-2.12.004 postcondition 2)
`--format json` selects JSON output. The `OutputFormat::Json` variant is set in `CliArgs`.
`main.rs` calls `reporter::format_json()` and writes the result to stdout.
- **Test:** `test_BC_2_12_004_format_json_produces_json_output()`

### AC-004 (traces to BC-2.12.004 postcondition 3 and invariant 2)
Any value other than `text` or `json` for `--format` causes an immediate exit 2 with a
usage error message on stderr. No file traversal occurs; no scanning is initiated.
`--format xml` and `--format TEXT` (uppercase) both trigger this path.
- **Test:** `test_BC_2_12_004_invalid_format_value_exits_2_before_scan()`

### AC-005 (traces to BC-2.12.004 postcondition 4 and invariant 1)
`--format` is case-sensitive. `text` and `json` are the only valid values (lowercase).
`--format TEXT`, `--format Json`, and `--format JSON` all cause exit 2 with usage error.
- **Test:** `test_BC_2_12_004_format_flag_is_case_sensitive()`

### AC-006 (traces to BC-2.12.004 invariant 2)
An invalid `--format` value triggers exit 2 BEFORE any file traversal begins.
Running `mdlinkcheck --format xml /dir-with-broken-links` exits 2 without emitting
any findings to stdout (the scan never starts).
- **Test:** `test_BC_2_12_004_invalid_format_exits_before_scanning()`

### AC-007 (traces to BC-2.14.004 postcondition 1)
`mdlinkcheck --help` prints the full usage text to stdout and exits 0. The usage text
contains the string `"Usage:"` (clap standard). stderr is empty.
- **Test:** `test_BC_2_14_004_help_exits_0_with_usage_on_stdout()`

### AC-008 (traces to BC-2.14.004 postcondition 2)
`mdlinkcheck --version` prints `mdlinkcheck X.Y.Z` (one line) to stdout and exits 0,
where X.Y.Z matches the `version` field in `Cargo.toml`. stderr is empty.
- **Test:** `test_BC_2_14_004_version_exits_0_with_semver_on_stdout()`

### AC-009 (traces to BC-2.14.004 postcondition 3 and postcondition 4)
No file traversal and no link scanning occur when `--help` or `--version` is passed.
Running `mdlinkcheck --help` or `mdlinkcheck --version` in a directory containing
broken links exits 0, not 1 or 2.
- **Test:** `test_BC_2_14_004_no_scanning_on_help_or_version()`

### AC-010 (traces to BC-2.14.004 postcondition 5)
stderr is empty for `--help` and `--version` invocations. No summary line is emitted
(there are no results to summarize).
- **Test:** `test_BC_2_14_004_stderr_empty_on_help_and_version()`

### AC-011 (traces to BC-2.14.004 invariant 3)
The version string printed by `--version` matches the `version` field in
`crates/mdlinkcheck/Cargo.toml` exactly. The build system (Cargo) provides this via
the `CARGO_PKG_VERSION` env var at compile time.
- **Test:** `test_BC_2_14_004_version_matches_cargo_toml()`

### AC-012 (traces to BC-2.14.004 invariant 4)
clap intercepts `--help` and `--version` before `app::run()` is called.
`verdict::exit_code()` is never invoked; no `DirIndex`, `AnchorIndex`, `Vec<Finding>`,
or `Vec<IoError>` is ever constructed for these invocations.
- **Test:** `test_BC_2_14_004_clap_intercepts_before_app_run()` (confirmed by the no-scan test AC-009 plus architectural constraint — `app::run()` is only reachable after clap succeeds with a real scan request)

## Forbidden Dependencies

`cli.rs` MUST NOT import from `reporter`, `verdict`, `scanner`, `http_client`, or `app`.
`cli.rs` produces `CliArgs` (including `OutputFormat` and `ReportOpts`) and returns them;
it never calls reporter or verdict functions directly.

`main.rs` MAY import from `cli`, `app`, and indirectly from `reporter` and `verdict` via
`app` — that is the intended shell-layer wiring. `main.rs` MUST NOT be imported by any other
module (it is the binary entry point).

## Previous Story Intelligence (MANDATORY)

| Story | Key Decisions | Patterns Established | Gotchas Discovered |
|-------|--------------|---------------------|-------------------|
| S-7.01 | `verdict::exit_code(findings, io_errors, config_error) -> u8` established; precedence: exit 2 > exit 1 > exit 0 | `main.rs` must pass all three args to `verdict::exit_code`; config_error comes from cli.rs glob validation, not from invalid `--format` | clap handles invalid `--format` at parse time (exit 2 from clap), NOT via `config_error = true` |
| S-7.02 | `reporter::format_text(findings, opts)` and `format_summary(findings)` established; `main.rs` routes format_text → stdout, format_summary → stderr | `format_summary()` is ALWAYS called regardless of format (text or JSON); summary always goes to stderr | `ColorMode` is in `ReportOpts`; pass `cli_args.report_opts` to `format_text()`, not a raw bool |
| S-7.03 | `reporter::format_json(findings, io_errors)` established; compact JSON, errors array separate from results | For JSON mode, `format_json()` receives both findings AND io_errors; `format_text()` receives only findings | JSON mode still calls `format_summary()` to stderr (BC-2.12.003 summary is always emitted regardless of format) |

_S-7.04 is the integration story that wires together all pure-core modules from S-7.01–S-7.03.
The most common mistake is forgetting to call `format_summary()` in JSON mode (summary is always
emitted regardless of `--format`). The second most common mistake is using `config_error = true`
for invalid `--format` — clap handles that at parse time, before `app::run()` is ever called._
