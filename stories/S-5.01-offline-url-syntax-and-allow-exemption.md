# S-5.01: Offline URL Syntax Validation and `--allow` Exemption

> **One-per-file:** This story is `S-5.01` in EPIC-05 — External URL Checking (`E-5`).
> Implements offline WHATWG URL syntax classification in `url_classifier.rs` and the
> `--allow` URL-prefix exemption hook in `filter.rs`. **OFFLINE ONLY — no network I/O,
> no HTTP status codes, no timeouts.** Conflating SS-09 (offline syntax) with SS-10
> (online liveness) is the specific damage that has been repaired once already; this story
> enforces the boundary.

## Narrative

- **As a** developer running `mdlinkcheck` (default offline mode)
- **I want to** have malformed external URLs (`http://` or `https://` scheme) reported as
  broken immediately, and valid-syntax URLs treated as clean without any network call
- **So that** CI pipelines get fast, deterministic link checking without network dependencies,
  and URLs matching `--allow` prefixes are silently exempted regardless of syntax or liveness

### AC-001 (traces to BC-2.09.001 postcondition 1)
`url_classifier::classify(dest: &str)` runs the destination string through the WHATWG URL
parser (`url::Url::parse()`) for any `dest` that begins with `http://` or `https://`. The
parse result — success or failure — is the sole input to the offline verdict.
- **Test:** `test_BC_2_09_001_whatwg_parse_invoked_for_http_dest()`

### AC-002 (traces to BC-2.09.001 postcondition 2)
When `url::Url::parse(dest)` returns an error for an `http://` or `https://` URL, the
verdict is `broken` with reason code `malformed-url`. The reason code is exactly
`malformed-url` (from the 13-code closed taxonomy in error-taxonomy.md).
- **Test:** `test_BC_2_09_001_parse_failure_yields_broken_malformed_url()`

### AC-003 (traces to BC-2.09.001 postcondition 3)
When `url::Url::parse(dest)` succeeds for an `http://` or `https://` URL, the verdict is
`clean`. A syntactically valid URL whose domain does not exist in DNS is still `clean`
offline — domain existence is irrelevant to offline syntax validation.
- **Test:** `test_BC_2_09_001_parse_success_yields_clean()`

### AC-004 (traces to BC-2.09.001 postcondition 4 and invariant 3)
In offline mode (absence of `--online` flag), `url_classifier` makes zero network calls
for any input. No ureq, reqwest, or std::net socket is opened. Syntax validation is the
ONLY check performed.
- **Test:** `test_BC_2_09_001_no_network_call_in_offline_mode()` (mock verifies no socket)

### AC-005 (traces to BC-2.09.001 invariant 1 and 2)
The WHATWG URL standard (via `url 2.5.8`) is the authority. A URL accepted by
`url::Url::parse()` is syntactically valid even if its domain has never been registered,
uses an unusual TLD, or contains query parameters and fragments.
- **Test:** `test_BC_2_09_001_whatwg_is_authority_for_validity()`

### AC-006 (traces to BC-2.09.002 postcondition 1)
When a URL is classified as `external-http` and matches an `--allow` prefix (per the
component-boundary algorithm in BC-2.11.002), the verdict is `clean` and the URL is not
validated or emitted in output. `filter::allow_match(url, prefixes)` is called before
`url_classifier::classify` in the Pass 2 pipeline; a matching URL never reaches
url_classifier.
- **Test:** `test_BC_2_09_002_allow_matching_url_yields_clean_no_check()`

### AC-007 (traces to BC-2.09.002 postcondition 2)
When a URL does NOT match any `--allow` prefix, normal SS-09 offline syntax validation
applies (ACs 001–005 above).
- **Test:** `test_BC_2_09_002_non_matching_url_reaches_ss09_validation()`

### AC-008 (traces to BC-2.09.002 invariant 1)
The matching algorithm (normalize-then-prefix-match with component-boundary check) is
exclusively defined in BC-2.11.002 and implemented in `filter::allow_match`. SS-09
(`url_classifier`) delegates the match decision: if `filter::allow_match` returns `true`,
url_classifier is not called for that URL. SS-09 has no knowledge of the matching
algorithm's internals.
- **Test:** `test_BC_2_09_002_ss09_does_not_reimplement_matching_algorithm()`

## Architecture Mapping

| Component | Module | Pure/Effectful |
|-----------|--------|---------------|
| URL syntax classification | `crates/mdlinkcheck-core/src/url_classifier.rs` | pure-core |
| UrlKind enum + associated types | `crates/mdlinkcheck-core/src/types.rs` | pure-core |
| Allow-prefix filter hook | `crates/mdlinkcheck-core/src/filter.rs` | pure-core |
| AllowPrefix type | `crates/mdlinkcheck-core/src/types.rs` | pure-core |

**SS-09 owns url_classifier:** SS-09 (`url_classifier.rs`) is pure core — `fn classify(dest: &str) -> UrlKind` with no I/O, anchored to SS-09 per ARCH-INDEX Subsystem Registry.

**SS-09 delegates to SS-11 for --allow:** The `filter::allow_match(url, &prefixes)` function (SS-11 filter.rs) is called first in Pass 2. If it returns `true`, the URL bypasses url_classifier entirely. This story implements both the url_classifier module and the allow_match call-site hook.

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-077 (id not authoritative — D-246) | `https://example.com/path?q=1&r=2#frag` (query + fragment in URL) | `clean` — WHATWG parses query+fragment correctly; offline |
| EC-078 (id not authoritative — D-246) | `http://` (scheme present, no host) | `broken` (malformed-url) — WHATWG rejects scheme-without-host |
| EC-082 (id not authoritative — D-246) | `https://user:pass@host.com/path` (auth credentials in URL) | `clean` — WHATWG accepts userinfo; credentials are a valid URL component |
| EC-083 (id not authoritative — D-246) | `https://[::1]:8080/path` (IPv6 literal in brackets) | `clean` — WHATWG accepts IPv6 literals; brackets are the correct syntax |
| EC-084 (id not authoritative — D-246) | `https://xn--nxasmq6b.com` (Punycode/IDN encoded host) | `clean` — WHATWG accepts Punycode ACE labels as syntactically valid |
| EC-200 | `--allow https://example.com`; URL `https://example.com/page` | `clean` (allow match; no validation) |
| EC-091 | `--allow https://example.com`; URL `https://example.com.evil.tld/` | normal SS-09 validation (component boundary: host differs; NOT allowed) |
| EC-space | `https://a b.com` (internal space) | `broken` (malformed-url) — WHATWG rejects spaces |
