# S-6.01: `--ignore` Glob Source Filtering and Anchor-Table Carve-Out

> EPIC-06 — Filter Application. One-per-file rule enforced.

## Narrative

- **As a** developer running `mdlinkcheck` in CI
- **I want to** exclude specific files (such as vendored or generated markdown) from link
  checking with `--ignore` glob patterns
- **So that** I get actionable findings only from files I own, while cross-file anchor links
  *into* excluded files continue to resolve correctly without false positives

## Behavioral Contracts

| BC | Title | Priority |
|----|-------|----------|
| BC-2.11.001 | `--ignore` Glob Exclusion (Source Files Only) | P0 |
| BC-2.11.003 | `--ignore` on Explicit PATH Argument | P1 |

## Acceptance Criteria

### AC-001 (traces to BC-2.11.001 postcondition 1)
When `--ignore 'vendor/**'` is provided and `vendor/lib.md` contains broken links, the
file's CWD-relative path matches the glob and the file is excluded as a link source —
no finding is emitted for links originating from `vendor/lib.md`.

**Test:** `test_BC_2_11_001_ignore_glob_excludes_source_file()`

### AC-002 (traces to BC-2.11.001 postcondition 2)
No finding has a `source_file` matching an `--ignore`'d path. The ignored file is not
scanned for links at all. If `vendor/lib.md` has ten broken links and is ignored, the
finding count is zero for that file.

**Test:** `test_BC_2_11_001_ignored_file_not_scanned_as_source()`

### AC-003 (traces to BC-2.11.001 postcondition 3)
The anchor table for an `--ignore`'d file IS still built during Pass 1. A link from a
non-ignored file to `vendor/lib.md#api-section` where `## Api Section` exists in
`vendor/lib.md` yields a `clean` verdict — not `broken(anchor-not-found)`.

**Test:** `test_BC_2_11_001_ignored_file_anchor_table_built()`

This is the DI-006 case 1 invariant and is verified by VP-016 Fixture 1
(vp016_ignored_file_is_valid_anchor_target). The test MUST include a control assertion
(a link to `definitely-not-here-xyzzy.md` that must be broken) to prevent a no-op
scanner from vacuously passing.

### AC-004 (traces to BC-2.11.001 invariant 1)
`--ignore` is source-only. It has no effect on whether a file can be an anchor target.
A file ignored as a source still appears in the AnchorIndex built during Pass 1.

**Test:** `test_BC_2_11_001_ignore_is_source_only_not_target()`

### AC-005 (traces to BC-2.11.001 invariant 2)
Glob matching uses globset 0.4.20 dialect: `*` does not cross `/`, but `**` does.
`--ignore 'vendor/**'` excludes `vendor/lib.md` and `vendor/sub/deep.md` but
`--ignore 'vendor/*'` excludes only `vendor/lib.md` (not `vendor/sub/deep.md`).

**Test:** `test_BC_2_11_001_double_star_crosses_directories()`

**D-246 NOTE:** EC-071 in BC-2.11.001's edge-case table (scenario: `--ignore 'vendor/**'`
excludes all files under `vendor/`) is non-authoritative per operator ruling D-246. The
acceptance criterion above is derived from the BC scenario text directly, NOT from
looking up EC-071 in test-vectors.md. See Edge Cases table for annotation.

### AC-006 (traces to BC-2.11.001 invariant 3)
The `--ignore` pattern is anchored at CWD, not at the git root. A pattern `docs/a.md`
matches only if the file's CWD-relative path is `docs/a.md`.

**Test:** `test_BC_2_11_001_pattern_anchored_at_cwd()`

### AC-007 (traces to BC-2.11.003 postcondition 1)
When a file is passed as an explicit PATH argument AND also matches an `--ignore` glob,
`--ignore` wins — the file is excluded as a link source (AMB-108 resolution per
interface-definitions.md §8 flag interaction rule). Running
`mdlinkcheck vendor/lib.md --ignore 'vendor/**'` where `vendor/lib.md` has broken links
produces exit 0 with no findings.

**Test:** `test_BC_2_11_003_ignore_wins_over_explicit_path()`

### AC-008 (traces to BC-2.11.003 postcondition 2)
A file excluded by `--ignore` over an explicit PATH argument is not scanned for links.
No finding has that file as `source_file`.

**Test:** `test_BC_2_11_003_explicit_path_ignored_not_scanned()`

### AC-009 (traces to BC-2.11.003 postcondition 3)
A file excluded by `--ignore` even when passed as an explicit PATH argument still has
its anchor table built — it remains a valid anchor target. A link to
`vendor/lib.md#heading` from another file resolves correctly.

**Test:** `test_BC_2_11_003_ignored_explicit_path_anchor_table_built()`

### AC-010 (traces to BC-2.11.003 invariant 1)
`--ignore` wins over explicit PATH. Always. This is a script-friendly design invariant
with no exceptions (interface-definitions.md §8, BC-2.11.003 invariant 1).

**Test:** `test_BC_2_11_003_ignore_always_wins_invariant()`

> **Note on BC-2.11.001 postcondition 4:** BC-2.11.001 PC4 states "--ignore does NOT
> affect files passed as explicit PATH arguments" but the inline [AMB-108] note
> immediately contradicts it: "--ignore wins over explicit PATH per
> interface-definitions.md §8". BC-2.11.003 is the canonical BC for this behavior and
> definitively establishes the --ignore-wins rule. ACs AC-007–AC-010 implement the
> AMB-108-resolved authoritative behavior from BC-2.11.003. No AC is derived from the
> literal main text of BC-2.11.001 PC4 to avoid asserting the negated (wrong) behavior.

> **Verification Properties:** BC-2.11.001 maps to VP-016 (integration test, test-sufficient
> tier per VP-INDEX v1.7 SS-11 table). BC-2.11.003 maps to test-sufficient (no formal VP).
> VP-016 is listed in frontmatter `verification_properties`. AC-003 directly implements
> VP-016 Fixture 1 behavior.

| EC-071 (id not authoritative — D-246) | `--ignore 'vendor/**'` — all files under `vendor/` excluded as sources | Exit 0; no findings from `vendor/`; anchor tables for `vendor/**` ARE built; links INTO `vendor/` files with valid anchors yield clean |

| EC-vendor-sub | `--ignore 'vendor/**'` with `vendor/sub/deep.md` | `vendor/sub/deep.md` excluded (** crosses directories) |
| EC-star-only | `--ignore 'vendor/*'` with `vendor/sub/deep.md` | `vendor/sub/deep.md` NOT excluded (* does not cross /) |
| EC-explicit-path-wins | `mdlinkcheck vendor/lib.md --ignore 'vendor/**'` | Exit 0; --ignore wins; `vendor/lib.md` not scanned as source; anchor table built |

| `filter` (`crates/mdlinkcheck-core/src/filter.rs`) | pure-core | Takes `&Path` + `&GlobSet`, returns `bool`. No I/O. Globset matching is deterministic. Kani-targetable. |

## Architecture Compliance Rules (MANDATORY)

| Rule | Source | Enforcement |
|------|--------|-------------|
| `filter.rs` must be in `mdlinkcheck-core` (pure-core crate), not in `mdlinkcheck` | ADR-001 (pure-core/effectful-shell boundary) | `cargo check -p mdlinkcheck-core` must compile cleanly; any fs:: or net:: import in filter.rs is a build error |
| `filter::ignore_match` must be pure: takes `(&Path, &GlobSet)`, returns `bool`, no side effects | ADR-001 | Kani-targetable requirement; confirmed by `purity-boundary-map.md` §Pure Core table |
| Workspace layout: `crates/mdlinkcheck-core/` (library) and `crates/mdlinkcheck/` (binary) | ADR-002 | Cargo.toml workspace members; incorrect placement causes linker failures |
| Pass 1 MUST build anchor tables for ALL discovered .md files including --ignore'd ones | ADR-007 (verdict model) + DI-006 | VP-016 Fixture 1 integration test; any implementation that skips ignored files entirely fails the control assertion |
| Glob matching MUST use globset 0.4.20 dialect (`**` crosses dirs; pattern anchored at CWD) | BC-2.11.001 invariant 2, module-decomposition §mdlinkcheck-core | `Cargo.toml` `[dependencies]` must declare `globset = "0.4.20"` exactly; no later minor versions without updating dependency-graph.md |
| scanner.rs must apply `filter::ignore_match` during traversal, not in app or main | Architecture boundary per module-decomposition.md §mdlinkcheck (Effectful Shell) | Code review: no call to filter::ignore_match in app.rs or main.rs (scanner is the traversal owner) |
