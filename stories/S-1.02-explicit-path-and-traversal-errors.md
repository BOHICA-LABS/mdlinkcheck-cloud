# S-1.02: Explicit PATH Arguments, Symlinks, Deduplication, and Traversal Error Cases

> **One-per-file:** This story is `S-1.02` in EPIC-01 — File Discovery and Scanning Pipeline (`E-1`).
> Extends `scanner.rs` with: explicit PATH argument handling (overriding CWD default), file-symlink
> following with dangling-symlink detection, path deduplication by canonicalized real path,
> empty-scan exit 0 with informational stderr message, and no-fail-fast I/O error handling with
> exit 2 precedence (DD-007, DI-011).

## Narrative

- **As a** developer or CI system using `mdlinkcheck`
- **I want to** pass explicit file or directory paths as arguments, have overlapping paths deduplicated, receive a `broken-symlink` verdict for dangling symlinks, see `No markdown files found.` when nothing is scanned, and continue scanning after a bad PATH rather than aborting immediately
- **So that** link checking is correct, non-aborting, and exits with the right code even under error conditions

## Acceptance Criteria

> **Verification Properties:** VP-005 (exit code 2 when any I/O error occurs; exit 2 beats exit 1 —
> Kani proof) is referenced in frontmatter per VP-INDEX v1.7. BC-2.01.002, BC-2.01.006,
> BC-2.01.007, and BC-2.01.008 are test-sufficient per VP-INDEX v1.7 (covered by acceptance corpus).

### AC-001 (traces to BC-2.01.002 postcondition 1)
When one or more PATH arguments are provided and a PATH is an existing directory, all `.md` files
under it are included in the scan set, subject to `.gitignore` exclusion, dot-dir skip, and
extension filter rules.
- **Test:** `test_BC_2_01_002_explicit_directory_path_scans_recursively()`

### AC-002 (traces to BC-2.01.002 postcondition 2)
When an explicit PATH argument resolves to an existing regular file, that file is included in the
scan set regardless of its extension (explicit intent overrides the extension filter, per AMB-006).
- **Test:** `test_BC_2_01_002_explicit_file_included_regardless_of_extension()`

### AC-003 (traces to BC-2.01.002 postcondition 3)
When a PATH argument does not exist, exit code 2 is triggered after all valid paths are scanned
(see AC-010 for full no-fail-fast behavior); see BC-2.01.009.
- **Test:** `test_BC_2_01_002_nonexistent_path_triggers_exit_2()`

### AC-004 (traces to BC-2.01.002 postcondition 4)
A file that would be discovered by multiple overlapping PATH arguments is included exactly once
in the scan set.
- **Test:** `test_BC_2_01_002_overlapping_paths_file_included_once()`

### AC-005 (traces to BC-2.01.002 invariant 1)
Deduplication is performed by canonicalized real path (resolving `.`, `..`, and file symlinks);
two PATH arguments that resolve to the same canonical path contribute one entry to the scan set.
- **Test:** `test_BC_2_01_002_dedup_by_canonical_path()`

### AC-006 (traces to BC-2.01.006 postcondition 1)
A file symlink whose target exists is followed; the target file is included in the scan set if
it matches the extension filter or was explicitly named.
- **Test:** `test_BC_2_01_006_valid_file_symlink_followed()`

### AC-007 (traces to BC-2.01.006 postcondition 2)
A file symlink whose target does not exist (dangling symlink) causes any Markdown link pointing
to that symlink path to receive verdict `broken` with reason `broken-symlink`. The reason
`broken-symlink` is distinct from `file-not-found`.
- **Test:** `test_BC_2_01_006_dangling_file_symlink_broken_symlink_reason()`

### AC-008 (traces to BC-2.01.006 invariant 2)
The reason code `broken-symlink` is distinct from `file-not-found` in the reason taxonomy;
a dangling symlink MUST NOT produce a `file-not-found` verdict.
- **Test:** `test_BC_2_01_006_broken_symlink_not_file_not_found()`

### AC-009 (traces to BC-2.01.007 postcondition 1)
Each canonical file path appears in the scan set exactly once regardless of how many overlapping
PATH arguments resolve to it (EC-010: `mdlinkcheck . docs docs/a.md`).
- **Test:** `test_BC_2_01_007_canonical_path_at_most_once_in_scan_set()`

### AC-010 (traces to BC-2.01.007 invariant 1)
Deduplication is applied before scanning begins; each file is processed exactly once, not once
per redundant PATH entry in the argument list.
- **Test:** `test_BC_2_01_007_dedup_before_scan_not_during_collection()`

### AC-011 (traces to BC-2.01.008 postcondition 1)
When traversal completes and zero `.md` files were found (after all filters applied), the tool
exits with code 0.
- **Test:** `test_BC_2_01_008_empty_scan_set_exits_zero()`

### AC-012 (traces to BC-2.01.008 postcondition 3)
When the scan set is empty, stderr contains exactly the informational message `No markdown files found.`; stdout is empty and no findings are emitted.
- **Test:** `test_BC_2_01_008_empty_scan_stderr_message()`

### AC-013 (traces to BC-2.01.008 invariant 2)
The `No markdown files found.` message is always emitted when the scan set is empty; there is
no `--quiet` flag to suppress it (D-011). The message is informational, not a warning.
- **Test:** `test_BC_2_01_008_no_quiet_flag_suppresses_message()`

### AC-014 (traces to BC-2.01.009 postcondition 1)
When a nonexistent PATH argument is provided, a `target-unreadable` error is recorded and an
error message is emitted on stderr; scanning continues for all remaining valid PATH arguments
without aborting (DD-007 no-fail-fast). This is NOT a startup configuration error.
- **Test:** `test_BC_2_01_009_nonexistent_path_records_error_scan_continues()`

### AC-015 (traces to BC-2.01.009 postcondition 2)
When an unreadable file is encountered during traversal (e.g., mode 000), a `target-unreadable`
I/O error is recorded; the scan continues for all other files; the final exit code is 2.
- **Test:** `test_BC_2_01_009_unreadable_file_records_error_scan_continues()`

### AC-016 (traces to BC-2.01.009 postcondition 3)
Findings from successfully scanned files are still emitted in output even when I/O errors occur
on other files (EC-185: `mdlinkcheck good_dir/ nonexistent_dir/` → good_dir findings + exit 2).
- **Test:** `test_BC_2_01_009_findings_still_emitted_with_io_error()`

### AC-017 (traces to BC-2.01.009 invariant 1)
Exit 2 takes precedence over exit 1 (DI-011). When both I/O errors and broken links occur in
the same run, the final exit code is 2.
- **Test:** `test_BC_2_01_009_exit_2_beats_exit_1()`

### AC-018 (traces to BC-2.01.009 invariant 3)
The `target-unreadable` reason is emitted in output to identify which file caused the I/O error;
this reason code appears in the `errors` array in JSON output, not in `results`.
- **Test:** `test_BC_2_01_009_target_unreadable_identifies_bad_file()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-007 | `mdlinkcheck notes.txt` — explicit non-`.md` file argument | `notes.txt` is included in the scan set; links inside are checked (explicit arg bypasses extension filter) |
| EC-010 | `mdlinkcheck . docs docs/a.md` — overlapping arguments | `docs/a.md` discovered via `.` traversal AND named explicitly; included exactly once; findings reported once |
| EC-012 | `mdlinkcheck /does/not/exist` — single nonexistent PATH, no other paths | Exit 2; `target-unreadable` on stderr; stdout empty; no findings (scan set is empty) |
| EC-013 | File with mode 000 encountered during traversal | `target-unreadable` error recorded; scan continues for other files; exit 2 |
| EC-038 | `[x](link.md)` where `link.md` is a dangling file symlink | Verdict `broken` with reason `broken-symlink`; NOT `file-not-found` |
| EC-028b | Symlink to valid file `target.md` | Followed; target processed normally; findings from target reported if any |
| EC-184 | Directory exists but contains zero `.md` files | Scan set empty; exit 0; stderr: `No markdown files found.` |
| EC-125 | `--ignore '*.md'` excludes all files (filter from BC-2.11) | Scan set empty; exit 0; stderr: `No markdown files found.` |
| EC-185 | `mdlinkcheck good_dir/ nonexistent_dir/` — `good_dir` has one broken link | Exit 2; broken finding from `good_dir` on stdout; `target-unreadable` for `nonexistent_dir` on stderr; `good_dir` fully scanned |
