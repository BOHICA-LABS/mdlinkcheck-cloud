# S-3.01: github-slugger v2 Slug Algorithm — Clean-Room Rust Reimplementation

> **One-per-file:** This story is `S-3.01` in EPIC-03 — Anchor Checking (`E-3`).
> Implements the `slug` pure-core module in `mdlinkcheck-core` as a clean-room Rust
> reimplementation of the github-slugger v2 algorithm from its behavioral specification.
> This is mdlinkcheck's headline differentiator (KD-001) — every anchor check depends
> on this algorithm being byte-for-byte identical to GitHub's rendering.

## Narrative

- **As a** link-checker user whose documentation is rendered on GitHub
- **I want** mdlinkcheck to compute heading anchor slugs using the exact github-slugger v2 algorithm
- **So that** anchor links that are valid on GitHub are reported clean, and links that differ from GitHub's actual anchors are reported broken — no false positives, no false negatives on slug computation

## Acceptance Criteria

> **Verification Properties (per VP-INDEX v1.7):**
> VP-001 (slug totality — Kani), VP-002 (slug determinism — Kani), VP-003 (duplicate
> injectivity — Kani), VP-012 (fuzz — P1), VP-018 (worked examples — unit),
> VP-026 (differential oracle against github-slugger@2.0.0 — proptest).
> All six referenced in frontmatter. Test names follow `test_BC_S_SS_NNN_*` convention.

### AC-001 (traces to BC-2.06.001 postcondition 1a)
The input to `compute_slug` is the heading's **rendered text content** — the concatenation of
text nodes from the AST event stream with inline markup stripped: bold/italic/link text nodes
retained (markup tokens discarded), code-span text nodes retained (backtick tokens discarded),
HTML element visible text retained (tag tokens stripped per DI-012 rule 1). Raw Markdown source
is never passed directly.
- **Test:** `test_BC_2_06_001_input_is_rendered_text_not_raw_source()`

### AC-002 (traces to BC-2.06.001 postcondition 1b)
`str::to_lowercase()` (full Unicode, not ASCII-only) is applied as the first transformation.
`## Ü Über` yields `"ü-über"` (Unicode case fold, not ASCII fold).
- **Test:** `test_BC_2_06_001_unicode_lowercase_not_ascii()`

### AC-003 (traces to BC-2.06.001 postcondition 1c)
Characters that are not `\p{Word}` (`char::is_alphanumeric() || c == '_'`), not `-`, and
not U+0020 space are removed. Punctuation such as `,`, `!`, `+`, `(`, `)`, `:` is removed.
- **Test:** `test_BC_2_06_001_non_word_chars_removed()`

### AC-004 (traces to BC-2.06.001 postcondition 1d)
Each U+0020 space is replaced with `-` in a 1:1 mapping — no run collapsing, no leading/trailing
trim. `## A  B` (two internal spaces) yields `"a--b"` (two hyphens), NOT `"a-b"`.
- **Test:** `test_BC_2_06_001_space_to_hyphen_one_to_one_no_collapse()`

### AC-005 (traces to BC-2.06.001 postcondition 2)
For any heading with at least one character surviving steps (b)–(d), the resulting slug is a
non-empty string. `## Hello, World!` → `"hello-world"`.
- **Test:** `test_BC_2_06_001_nonempty_heading_yields_nonempty_slug()`

### AC-006 (traces to BC-2.06.001 postcondition 3)
A heading whose text yields an empty string after all steps (e.g., a heading containing ONLY
punctuation such as `## !!!`) produces slug `""` (empty string) and an empty-string entry is
added to the anchor table for github-slugger v2 compatibility.
- **Test:** `test_BC_2_06_001_pure_punctuation_heading_yields_empty_slug()`

### AC-007 (traces to BC-2.06.001 postcondition 4–6)
The three canonical DD-015 examples produce the correct slugs:
- `## Hello, World!` → `"hello-world"` (comma removed, space→hyphen)
- `## C++ Guide` → `"c-guide"` (both `+` chars removed as non-\p{Word})
- `## 日本語` → `"日本語"` (\p{Word} includes Unicode letters; no change)
- **Test:** `test_BC_2_06_001_dd015_canonical_examples()`

### AC-008 (traces to BC-2.06.001 invariant 2 — HTML text retention)
For a heading `## <kbd>Ctrl+C</kbd>`, the HTML tag tokens are stripped but the visible text
`Ctrl+C` is retained per DI-012 rule 1 (pulldown-cmark InlineHtml event model, ADR-003). The
rendered text is `"ctrλc"` after `+` removal — specifically: `"Ctrl+C"` lowercased `"ctrl+c"`,
`+` stripped → `"ctrlc"`, slug `"ctrlc"`. A heading `` ## `foo` bar `` (code span) retains
`foo` and `bar`, rendering `"foo bar"` → slug `"foo-bar"`.
- **Test:** `test_BC_2_06_001_html_tag_stripped_text_retained()`
- **Test:** `test_BC_2_06_001_code_span_text_retained()`

### AC-009 (traces to BC-2.06.002 postcondition 1)
When `occurrences` does NOT contain the slug as a key (first occurrence): emit the slug
unchanged and insert `occurrences[slug] = 1`.
- **Test:** `test_BC_2_06_002_first_occurrence_emitted_unchanged()`

### AC-010 (traces to BC-2.06.002 postcondition 2)
When `occurrences` contains the slug (a duplicate), apply the while-loop: start at `count =
occurrences[slug]`, form `result = "{slug}-{count}"`, increment `count` while `result` is also
in `occurrences`. Emit `result`; set `occurrences[result] = 1`; update `occurrences[slug] = count + 1`.
- **Test:** `test_BC_2_06_002_duplicate_counter_while_loop()`

### AC-011 (traces to BC-2.06.002 postcondition 3)
Canonical triple-collision in document order (both `## Setup` precede `## Setup 1`):
- First `## Setup` → `"setup"`
- Second `## Setup` → `"setup-1"`
- `## Setup 1` → raw slug `"setup-1"` is already in occurrences → bumped to `"setup-1-1"`
- **Test:** `test_BC_2_06_002_canonical_triple_collision_setup_x2_then_setup1()`

### AC-012 (traces to BC-2.06.002 postcondition 4)
Setup-1-first order (`## Setup 1` before both `## Setup`):
- `## Setup 1` → `"setup-1"` (key-absent)
- First `## Setup` → `"setup"` (key-absent)
- Second `## Setup` → `"setup-1"` is taken → `"setup-2"`
- **Test:** `test_BC_2_06_002_setup_1_first_order_collision_resolution()`

### AC-013 (traces to BC-2.06.002 invariant 1)
The `occurrences` counter map is per-file — it is reset to an empty map for each new file's
heading sequence. Duplicate counters from one file do not carry over to the next.
- **Test:** `test_BC_2_06_002_counter_resets_between_files()`
