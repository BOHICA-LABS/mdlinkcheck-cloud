# S-5.02: `http_verdict` — Pure HTTP Response Classification

> **One-per-file:** This story is `S-5.02` in EPIC-05 — External URL Checking (`E-5`).
> Implements the pure-core `http_verdict::classify_response` function, which is the
> **only** piece of SS-10 that can be formally verified with Kani (VP-007). This module
> must be complete and Kani-proven before S-5.03 and S-5.04 (the effectful http_client)
> can be dispatched.

## Narrative

- **As a** formal-verifier and test-writer
- **I want to** have a pure, total function `classify_response(status: u16, attempt: HttpAttempt) -> Verdict`
  that partitions every HTTP status code and both request-attempt types into exactly one verdict
- **So that** VP-007 Kani proof can exhaust all 65 536 × 2 input combinations, and http_client
  can delegate all response-classification logic here rather than embedding it in effectful code

## Acceptance Criteria

> **Verification Properties:** VP-007 (`http_verdict::classify_response` Kani totality +
> correctness proof, P0) is referenced in frontmatter per VP-INDEX v1.7 for BC-2.10.002.
> VP-007 harness covers the status-code partition (all u16 × {Head, GetFallback}). The
> transport-error partition (dns-failure, tls-error, timeout) is PENDING HttpAttempt
> transport-error API extension; those harnesses are design sketches only and cannot run
> against the declared API. See VP-007 v1.3 and the Verification Gap note below.
>
> **D-246 NOTICE:** EC-088 citation in BC-2.10.002 is NOT authoritative (D-246). The BC
> scenario text (HTTP 503) is authoritative; the registry entry for EC-088 describes an
> unrelated scenario (DNS NXDOMAIN).

> **Verification Gap (VP-007 status-code harness only):** VP-007 Kani proves the HTTP
> status-code partition (PC0–PC11, PC15) and correctness constraints: 429/5xx never broken,
> 404/410 always broken, 400-after-GET indeterminate (D-018). The transport-layer partition
> (PC12 timeout, PC13 dns-failure, PC14 tls-error) requires `classify_response_with_error`
> or `HttpError` enum — neither exists in the declared API (`api-surface.md`: only
> `classify_response(status: u16, attempt: HttpAttempt)`). Those harnesses are commented
> out pending API extension. BC-2.10.005 and BC-2.10.006 are covered by S-5.04 at the
> test-sufficient level until the API is extended.

### AC-001 (traces to BC-2.10.002 postcondition 1)
`classify_response(status, attempt)` returns `Verdict::Clean` for all `status` values
in 200..=299, regardless of `attempt` variant. Liveness outcome `alive` maps to link
verdict `clean` per DD-022.
- **Test:** `test_BC_2_10_002_2xx_yields_clean()`

### AC-002 (traces to BC-2.10.002 postcondition 6)
`classify_response(404, attempt)` returns `Verdict::Broken(BrokenReason::HttpError)` for
all `attempt` variants (both `Head` and `GetFallback`). Reason code is `http-error` exactly.
- **Test:** `test_BC_2_10_002_404_yields_broken_http_error()`

### AC-003 (traces to BC-2.10.002 postcondition 8)
`classify_response(410, attempt)` returns `Verdict::Broken(BrokenReason::HttpError)` for
all `attempt` variants. `410 Gone` is a definitive broken signal alongside 404.
- **Test:** `test_BC_2_10_002_410_yields_broken_http_error()`

### AC-004 (traces to BC-2.10.002 postcondition 9 and invariant 1)
`classify_response(429, attempt)` returns `Verdict::Indeterminate(IndeterminateReason::HttpIndeterminate)`
for all `attempt` variants. 429 is NEVER `broken`. This is DI-010 enforcement.
- **Test:** `test_BC_2_10_002_429_yields_indeterminate_never_broken()`

### AC-005 (traces to BC-2.10.002 postcondition 11 and invariant 1)
For all `status` in 500..=599, `classify_response(status, attempt)` returns
`Verdict::Indeterminate`. 5xx responses are NEVER `broken`. This is DI-010 enforcement.
- **Test:** `test_BC_2_10_002_5xx_range_yields_indeterminate_never_broken()`

### AC-006 (traces to BC-2.10.002 postcondition 3 — D-018)
`classify_response(400, HttpAttempt::GetFallback)` returns `Verdict::Indeterminate`. 400
received after a GET fallback is indeterminate, not broken (D-018 operator ruling: 400 can
reflect server-side method validation, not link non-existence).
- **Test:** `test_BC_2_10_002_400_after_get_fallback_is_indeterminate_d018()`

### AC-007 (traces to BC-2.10.002 postconditions 4 and 5)
`classify_response(401, attempt)` and `classify_response(403, attempt)` return
`Verdict::Indeterminate` for all `attempt` variants. Auth walls and bot-blocking are
indeterminate — the resource exists behind access control.
- **Test:** `test_BC_2_10_002_401_403_yields_indeterminate()`

### AC-008 (traces to BC-2.10.002 postcondition 0)
For all `status` in 0..=99 and 100..=199 (informational), `classify_response(status, attempt)`
returns `Verdict::Indeterminate`. Non-standard and informational codes are the catch-all
for any status not explicitly enumerated.
- **Test:** `test_BC_2_10_002_catch_all_low_and_1xx_yields_indeterminate()`

### AC-009 (traces to BC-2.10.002 postcondition 10)
For all `status` in {400, 402, 406..=409, 411..=428, 430..=499} (other 4xx excluding
401/403/404/405/410), `classify_response(status, attempt)` returns `Verdict::Indeterminate`.
(Note: 400 on HEAD is also indeterminate when no GET fallback was triggered.)
- **Test:** `test_BC_2_10_002_other_4xx_yields_indeterminate()`

### AC-010 (traces to BC-2.10.002 invariant 3)
`classify_response` is **total**: it terminates and returns a `Verdict` for every possible
`u16` value and every `HttpAttempt` variant, without panicking, unwrapping, or
branching to unreachable code.
- **Test:** `test_BC_2_10_002_totality_no_panic_for_any_u16()` (exhaustive table; Kani VP-007 proves this formally)

### AC-011 (traces to BC-2.10.002 invariant 2)
Among HTTP status codes, **only** 404 and 410 (i.e., after the full HEAD+GET fallback
sequence resolves to one of these) produce `Verdict::Broken`. No other 4xx, no 5xx, and
no informational code produces `Verdict::Broken`.
- **Test:** `test_BC_2_10_002_only_404_410_are_broken_among_4xx()`

## Architecture Mapping

| Component | Module | Pure/Effectful |
|-----------|--------|---------------|
| HTTP response classification function | `crates/mdlinkcheck-core/src/http_verdict.rs` | pure-core |
| `HttpAttempt` enum | `crates/mdlinkcheck-core/src/types.rs` | pure-core |
| `Verdict`, `BrokenReason`, `IndeterminateReason` | `crates/mdlinkcheck-core/src/types.rs` | pure-core |

**Pure/effectful seam:** `http_verdict.rs` is the pure-core half of SS-10. It receives a
`(u16, HttpAttempt)` pair and returns a `Verdict` — zero I/O, zero mutable state, fully
Kani-targetable. `http_client.rs` (S-5.03/S-5.04) is the effectful half: it issues HTTP
requests, inspects response status codes, and calls `classify_response`. The seam is the
`(status: u16, attempt: HttpAttempt)` pair — a minimal, pure-core-safe input.

## Edge Cases

> **D-246 NOTICE:** EC-088 citation in BC-2.10.002 is NOT authoritative (D-246 /
> ec-injectivity-adjudication.md). The BC documents HTTP 503 → indeterminate (5xx branch);
> the registry EC-088 describes DNS NXDOMAIN. Scenario text from BC-2.10.002 is used below.

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-088 (id not authoritative — D-246) | HTTP 503 Service Unavailable | `Verdict::Indeterminate` (5xx branch, PC11) |
| EC-089 | HTTP 410 Gone | `Verdict::Broken(http-error)` |
| EC-198 | HTTP 429 Too Many Requests | `Verdict::Indeterminate(http-indeterminate)` — never broken |
| EC-201 | HTTP 401 (private repo / auth wall) | `Verdict::Indeterminate(http-indeterminate)` |
| EC-087 | Self-signed TLS cert → tls-error | `Verdict::Broken(tls-error)` — pending API extension; transport-error variants not in declared API; test-sufficient in S-5.04 |
| EC-HEAD-405-GET-405 | HEAD 405 → GET 405 (both methods rejected) | `Verdict::Indeterminate` (GET-also-405 case, PC7) |
| EC-D018 | HEAD returns 405; GET returns 400 | `Verdict::Indeterminate` (D-018: 400-after-GET) |
| EC-1xx | HTTP 100 Continue | `Verdict::Indeterminate` (catch-all PC0) |

## Purity Classification

| Module | Classification | Justification |
|--------|---------------|---------------|
| `crates/mdlinkcheck-core/src/http_verdict.rs` | pure-core | `fn classify_response(status: u16, attempt: HttpAttempt) -> Verdict`. Pattern-match on integers. No I/O. Kani-targetable per ADR-001. |

**Forbidden Dependencies (build-time enforcement):**
- `http_verdict.rs` MUST NOT import `ureq`, `reqwest`, `tokio`, `std::net`, `http_client`,
  `url_classifier`, or any crate or module that performs I/O. The `http_verdict` module has
  zero external crate dependencies beyond `mdlinkcheck-core/src/types.rs`. If it gains a
  network or I/O dependency, the Kani proof is invalidated.
