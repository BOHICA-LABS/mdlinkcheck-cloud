# S-1.03: Markdown File Reading, BOM/CRLF Normalization, and pulldown-cmark Event Stream

> **One-per-file:** This story is `S-1.03` in EPIC-01 — File Discovery and Scanning Pipeline (`E-1`).
> Implements the file-reading pipeline in `scanner.rs`: reads raw bytes, strips any UTF-8 BOM,
> normalizes CRLF to LF, validates UTF-8, then passes the clean string to
> `pulldown_cmark::Parser::new_ext()` with GFM options and collects the event stream via
> `into_offset_iter()`. Produces the `ParsedFile` struct consumed by all downstream pure-core
> modules.

## Narrative

- **As a** downstream pure-core module (`link_extractor`, `anchor_table`)
- **I want to** receive a clean, BOM-free, LF-only UTF-8 string paired with a byte-offset event stream and a precomputed line-start map
- **So that** link extraction, anchor table construction, and `(line, column)` reporting all operate on a consistent, normalized representation without any BOM-offset skew or CRLF-counting mismatches

### AC-001 (traces to BC-2.02.002 postcondition 1)
The string delivered to `pulldown_cmark::Parser::new_ext()` and to all pure-core modules is
BOM-free: `scanner.rs` detects and strips a UTF-8 BOM (bytes 0xEF 0xBB 0xBF at offset 0) from
the raw byte buffer before any further processing.
- **Test:** `test_BC_2_02_002_bom_stripped_before_parser()`

### AC-002 (traces to BC-2.02.002 postcondition 2)
The string delivered to the parser and all pure-core modules contains only LF line endings
(0x0A); `scanner.rs` replaces all CRLF sequences (0x0D 0x0A) with LF in the byte buffer before
constructing the UTF-8 string.
- **Test:** `test_BC_2_02_002_crlf_normalized_to_lf()`

### AC-003 (traces to BC-2.02.002 postcondition 5)
Column numbers in findings are measured from position 0 of the BOM-stripped, LF-normalized
buffer. A file with a UTF-8 BOM whose first real character (after the 3-byte BOM) is `[` reports
that `[` at column 1, not column 4.
- **Test:** `test_BC_2_02_002_column_one_after_bom_strip()`

### AC-004 (traces to BC-2.02.002 invariant 1)
BOM detection and stripping are exclusively the responsibility of `scanner.rs` (effectful shell).
No pure-core module (`link_extractor`, `anchor_table`, `slug`, `path_resolver`, etc.) inspects
raw bytes for BOM presence.
- **Test:** `test_BC_2_02_002_bom_handling_in_scanner_only()`

### AC-005 (traces to BC-2.02.002 invariant 2)
CRLF normalization is exclusively the responsibility of `scanner.rs`. No pure-core module
performs `str::replace("\r\n", "\n")` or equivalent.
- **Test:** `test_BC_2_02_002_crlf_normalization_in_scanner_only()`

### AC-006 (traces to BC-2.02.002 invariant 3)
The raw source file on disk is NEVER modified. BOM stripping and CRLF normalization are
in-memory operations only; the original file bytes are unchanged after the scan.
- **Test:** `test_BC_2_02_002_source_file_unchanged_on_disk()`

### AC-007 (traces to BC-2.02.001 postcondition 1)
Each discovered `.md` file is parsed into a sequence of pulldown-cmark events with byte-range
annotations using `Parser::new_ext(source, Options::all())` followed by `into_offset_iter()`;
this yields `(Event<'_>, Range<usize>)` pairs for every structural element.
- **Test:** `test_BC_2_02_001_parser_produces_offset_events()`

### AC-008 (traces to BC-2.02.001 postcondition 2)
Each link and heading event carries a byte offset that is correctly convertible to a 1-based
`(line, column)` pair by binary-searching the precomputed line-start array stored in
`ParsedFile::link_line_map`.
- **Test:** `test_BC_2_02_001_byte_offset_to_line_col_conversion()`

### AC-009 (traces to BC-2.02.001 postcondition 3)
The byte offset for a link event is the position of the opening `[` for inline/reference links,
or the `#` for ATX headings, as produced by `pulldown-cmark`'s `into_offset_iter()`.
- **Test:** `test_BC_2_02_001_link_offset_at_opening_bracket()`

### AC-010 (traces to BC-2.02.001 postcondition 4)
GFM extensions (tables, strikethrough, task lists) are enabled via `Options::all()`; footnotes
are recognized as events but treated as non-links (no `Tag::Link` event emitted for footnotes).
- **Test:** `test_BC_2_02_001_gfm_extensions_enabled()`

### AC-011 (traces to BC-2.02.001 invariant 1)
Parsing is purely structural; no regex is applied to the source text after the pulldown-cmark
event stream is produced. Link destinations are extracted directly from `Tag::Link` and
`Tag::Image` event payloads.
- **Test:** `test_BC_2_02_001_no_regex_on_source()`

### AC-012 (traces to BC-2.02.001 invariant 3)
Line numbers in `ParsedFile::link_line_map` are 1-based; column numbers derived from byte
offsets are 1-based relative to the start of the line in the normalized buffer.
- **Test:** `test_BC_2_02_001_one_based_line_and_column()`

### AC-013 (traces to BC-2.02.001 invariant 2)
Code contexts (inline code spans, fenced code blocks, indented code blocks) are distinguishable
by pulldown-cmark event type alone — links inside code contexts arrive as `Event::Code` or
`Event::Text` inside `Tag::CodeBlock`, never as `Tag::Link` events — so no heuristic is needed
to satisfy DI-004.
- **Test:** `test_BC_2_02_001_code_context_events_distinguishable()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-015 | UTF-8 BOM at start of file followed by `## Setup` heading | BOM stripped; heading at line 1, column 1 (after BOM removal); `#` at byte 0 of normalized string |
| EC-015b | BOM file: `[x](missing.md)` is the first link on line 1 | Exit 1; link reported at line 1, column 1 (NOT column 4 — BOM stripped before column counting) |
| EC-016 | CRLF file with link on line 10 | CRLF normalized to LF; link reported at line 10 (same as equivalent LF file) |
| EC-121 | Multi-line link destination spanning two source lines | pulldown-cmark handles this; reported position is the byte offset of the opening `[` regardless of destination extent |
