# S-1.04: Non-UTF-8 File Error Handling and Explicit Non-.md Argument Parsing

> **One-per-file:** This story is `S-1.04` in EPIC-01 — File Discovery and Scanning Pipeline (`E-1`).
> Completes the scanning pipeline error paths: when `scanner.rs` encounters a file that cannot be
> decoded as valid UTF-8, it records a `target-unreadable` I/O error and continues scanning all
> other files (no-fail-fast, DD-007). When a file is passed as an explicit PATH argument regardless
> of its extension, it is parsed as Markdown. Both behaviors reuse the `IoError`/`Vec<IoError>`
> machinery established in S-1.02.

## Narrative

- **As a** developer using `mdlinkcheck`
- **I want to** receive a clear `target-unreadable` error when a `.md` file contains non-UTF-8 bytes, continue scanning other files rather than aborting, and be able to explicitly pass non-`.md` files for link checking
- **So that** CI pipelines don't silently fail on encoding issues, findings from healthy files are never lost due to one bad file, and non-standard file extensions can be checked when explicitly named

### AC-001 (traces to BC-2.02.003 postcondition 1)
When a file in the scan set contains bytes that are not valid UTF-8, the file is not parsed;
no links or headings are extracted from it.
- **Test:** `test_BC_2_02_003_non_utf8_file_not_parsed()`

### AC-002 (traces to BC-2.02.003 postcondition 2)
When a non-UTF-8 file is encountered, a `target-unreadable` finding is emitted for that file.
The reason code is exactly `target-unreadable` — not `file-not-found`, not `broken`, not any
other code from the 13-code closed taxonomy.
- **Test:** `test_BC_2_02_003_non_utf8_emits_target_unreadable_reason()`

### AC-003 (traces to BC-2.02.003 postcondition 3)
When a non-UTF-8 file is encountered, the scan continues normally for all other files in the
scan set; no fail-fast abort occurs (DD-007 no-fail-fast).
- **Test:** `test_BC_2_02_003_scan_continues_after_non_utf8()`

### AC-004 (traces to BC-2.02.003 postcondition 4)
The final exit code is 2 when any non-UTF-8 file is encountered, because a non-UTF-8 file is
classified as an I/O error and `verdict::exit_code` returns 2 when `io_errors` is non-empty
(DI-011 — I/O error exit 2 takes precedence over broken-link exit 1).
- **Test:** `test_BC_2_02_003_exit_2_on_non_utf8()`

### AC-005 (traces to BC-2.02.003 invariant 1)
A non-UTF-8 file is classified as an I/O error (`target-unreadable`), NOT as a broken link. The
tool does NOT attempt lossy UTF-8 decoding (e.g., no `String::from_utf8_lossy()`).
- **Test:** `test_BC_2_02_003_no_lossy_utf8_decoding()`

### AC-006 (traces to BC-2.02.003 invariant 2)
`target-unreadable` is the reason code (not `file-not-found`). A non-UTF-8 file is distinct
from a missing file even though both produce exit 2.
- **Test:** `test_BC_2_02_003_target_unreadable_not_file_not_found()`

### AC-007 (traces to BC-2.02.003 invariant 3)
No fail-fast: when 3 files are in the scan set and 1 is non-UTF-8, findings from the other 2
are still collected and emitted (EC-014 test vector: 1 valid file, 1 non-UTF-8 → findings from
valid file present + `target-unreadable` for bad file).
- **Test:** `test_BC_2_02_003_findings_from_other_files_still_emitted()`

### AC-008 (traces to BC-2.02.004 postcondition 1)
When a PATH argument resolves to an existing regular file regardless of its extension (e.g.,
`notes.txt`, `notes.html`), the file is read and parsed as Markdown; all links found in it are
checked and findings reported normally.
- **Test:** `test_BC_2_02_004_explicit_non_md_file_parsed_as_markdown()`

### AC-009 (traces to BC-2.02.004 postcondition 2)
All links found in an explicitly-named non-`.md` file are checked; exit code reflects the
presence or absence of broken links exactly as for `.md` files.
- **Test:** `test_BC_2_02_004_links_in_explicit_non_md_file_checked()`

### AC-010 (traces to BC-2.02.004 invariant 1)
The extension-bypass rule applies ONLY to explicit PATH arguments. Files discovered via
directory traversal still use the `.md`-only case-sensitive extension filter from BC-2.01.005.
A `notes.txt` in a traversed directory is excluded; `notes.txt` passed explicitly is included.
- **Test:** `test_BC_2_02_004_extension_bypass_only_for_explicit_args()`

### AC-011 (traces to BC-2.02.004 invariant 2)
If an explicitly-named file exists but cannot be read (e.g., permission denied, non-UTF-8
content), BC-2.02.003 applies: `target-unreadable` is emitted and the scan continues.
- **Test:** `test_BC_2_02_004_unreadable_explicit_file_applies_bc_2_02_003()`

## Architecture Mapping

| Component | Module | Pure/Effectful |
|-----------|--------|---------------|
| UTF-8 validation failure detection | `crates/mdlinkcheck/src/scanner.rs` (`String::from_utf8()` error path) | effectful-shell |
| `target-unreadable` I/O error recording | `crates/mdlinkcheck/src/scanner.rs` (into `Vec<IoError>`) | effectful-shell |
| No-fail-fast scan continuation | `crates/mdlinkcheck/src/scanner.rs` (error recorded, loop continues) | effectful-shell |
| Explicit file path inclusion (no extension check) | `crates/mdlinkcheck/src/scanner.rs` (skip extension filter for explicit args) | effectful-shell |
| Exit code 2 for I/O errors | `crates/mdlinkcheck-core/src/verdict.rs` (`exit_code(findings, io_errors, config_error)`) | pure-core |

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-014 | File containing ISO-8859-1 bytes (non-UTF-8) in a 2-file scan set; other file is valid | Exit 2; `target-unreadable` for the ISO-8859-1 file; findings from the valid file present |
| EC-007 | `mdlinkcheck notes.txt` where `notes.txt` has `[x](missing.md)` | Exit 1; 1 finding reported from `notes.txt` (parsed as Markdown despite `.txt` extension) |
| EC-007b | `mdlinkcheck notes.html` where `notes.html` has an inline Markdown link | Exit 1 if pulldown-cmark finds a `Tag::Link` event; parsed as Markdown |

## Purity Classification

| Module | Classification | Justification |
|--------|---------------|---------------|
| `crates/mdlinkcheck/src/scanner.rs` (UTF-8 error path) | effectful-shell | `String::from_utf8()` is a computation on already-read bytes; co-located in scanner (effectful boundary) because the read itself is I/O; ADR-001 |
| `crates/mdlinkcheck-core/src/verdict.rs` | pure-core | `exit_code(findings, io_errors, config_error) -> u8` — pure aggregation; no I/O; Kani-targetable for VP-005 (already introduced in S-1.02) |

## Architecture Compliance Rules (MANDATORY)

| Rule | Source | Enforcement |

| Non-UTF-8 MUST produce `target-unreadable` reason code (the closed-set code from error-taxonomy.md §2.4) | BC-2.02.003 postcondition 2; error-taxonomy.md §3 closed-set invariant | Test AC-002: reason code string exactly equals `target-unreadable` |
