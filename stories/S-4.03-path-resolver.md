# S-4.03: Pure Path Resolver — NFC Case-Sensitive Resolution, Directory and Non-Markdown Routing, Trailing Slash, and Root-Relative Links

> **One-per-file:** This story is `S-4.03` in EPIC-04 — Relative File Link Resolution (`E-4`).
> Implements `path_resolver.rs` — the pure-core module that takes a link destination (already
> split by `fragment::split` from S-4.02), a source directory, a git root, and a `DirIndex`
> (from S-4.01), and returns a `PathVerdict` without any I/O. This module is the core of
> KD-004 (case-correct path resolution): it resolves `.`/`..` logically, looks up entries in
> `DirIndex` using NFC case-sensitive exact matching (never delegating to macOS APFS), routes
> directory targets and non-Markdown targets correctly, and handles trailing-slash and
> root-relative edge cases. Delivers VP-008 (NFC comparison proptest), VP-009 (NFC idempotent
> proptest), and VP-024 (trailing-slash-on-file proptest).

## Narrative

- **As a** developer or CI system running `mdlinkcheck` on a macOS APFS filesystem
- **I want** link verdicts to depend only on repository content (exact byte-for-byte filenames)
  and not on macOS APFS case-folding
- **So that** `[x](readme.md)` where the file is `README.md` is correctly reported as
  `broken(file-not-found)` on macOS — and `[x](café.md)` where the file is stored in NFD on
  APFS normalizes to NFC on both sides and is correctly reported as `clean` — giving
  byte-identical output regardless of which macOS machine runs the check (DI-001 determinism,
  NFR-003 reproducibility, D-043 macOS-only determinism rationale)

### AC-001 (traces to BC-2.07.001 postcondition 1)
`path_resolver::resolve(dest, src_dir, git_root, index)` resolves relative file destinations
by joining the source file's parent directory with the destination path:
`resolved = src_dir.join(dest_path).canonicalize_logical()`. For `[x](../api/ref.md)` in
`docs/guide.md`, the resolved path is `api/ref.md` from repo root.
- **Test:** `test_BC_2_07_001_relative_path_joined_to_source_dir()`

### AC-002 (traces to BC-2.07.001 postcondition 2)
`..` segments are resolved logically (not by `std::fs::canonicalize` or `readlink`). The
function computes the canonical path by iterating path components and maintaining a stack
(pushing normal components, popping on `..`, ignoring `.`). No filesystem call is needed
for `.`/`..` resolution — the logical result is computed from the path string alone.
- **Test:** `test_BC_2_07_001_dotdot_resolved_logically_no_readlink()`

### AC-003 (traces to BC-2.07.001 postcondition 4)
After logical resolution, DI-002 case-sensitive NFC comparison is applied: the resolved
destination is NFC-normalized and compared against NFC-normalized actual directory entries
from `DirIndex`. The pure-core function returns the correct verdict based solely on `DirIndex`
data — no additional I/O.
- **Test:** `test_BC_2_07_001_nfc_comparison_applied_after_resolution()`

### AC-004 (traces to BC-2.07.001 invariant 2)
Path resolution is purely logical. No call to `std::fs::canonicalize`, `std::fs::read_link`,
`std::fs::metadata`, or `Path::exists` is made inside `path_resolver::resolve`. All existence
and kind information comes from the provided `DirIndex`. Verified by: (a) the module compiles
without `std::fs` imports, and (b) the function is called in unit tests with a fully synthetic
`DirIndex` containing no real filesystem paths.
- **Test:** `test_BC_2_07_001_no_filesystem_calls_in_resolve()` (pure-function test: synthetic DirIndex)

### AC-005 (traces to BC-2.07.002 postcondition 1)
For a root-relative destination (starts with `/`), the resolved path is
`git_root.join(dest.strip_prefix('/'))`. For `[x](/docs/api.md)` in a git repo rooted at
`/Users/user/project`, the resolved path is `/Users/user/project/docs/api.md`.
- **Test:** `test_BC_2_07_002_root_relative_uses_git_root()`

### AC-006 (traces to BC-2.07.002 postcondition 2)
When `git_root` is the scan root (non-git fallback), root-relative destination
`[x](/docs/api.md)` resolves to `scan_root.join("docs/api.md")`. The resolver receives the
already-determined root as input — it does not run `git rev-parse` itself.
- **Test:** `test_BC_2_07_002_root_relative_uses_scan_root_fallback()`

### AC-007 (traces to BC-2.07.002 invariant 1)
All root-relative links in the same run resolve using the same git root value. This is enforced
by `path_resolver` receiving a single immutable `git_root: &Path` argument for the entire
Pass 2. No per-link or per-file root determination is done inside the resolver.
- **Test:** `test_BC_2_07_002_same_root_for_all_root_relative_links()`

### AC-008 (traces to BC-2.07.003 postcondition 1)
Both the resolved destination path component and all actual directory entry names in `DirIndex`
are NFC-normalized before comparison. `path_resolver::resolve` calls
`unicode_normalization::UnicodeNormalization::nfc()` on both sides before the byte-for-byte
string comparison.
- **Test:** `test_BC_2_07_003_nfc_applied_to_both_sides_of_comparison()`

### AC-009 (traces to BC-2.07.003 postcondition 3)
`[x](readme.md)` where the actual file is `README.md` produces `broken(file-not-found)` —
even on macOS APFS. The comparison is byte-for-byte after NFC normalization; it is NOT
delegated to the OS filesystem. Case mismatch is a different byte sequence after NFC and is
therefore not a match.
- **Test:** `test_BC_2_07_003_case_mismatch_produces_file_not_found_on_macos()` (VP-008 proptest
  also covers this; this is the concrete acceptance test)

### AC-010 (traces to BC-2.07.003 postcondition 4)
`[x](café.md)` (NFC U+00E9) linking to a file stored as `cafe\u{301}.md` (NFD, APFS default):
after NFC normalization on both sides, both normalize to `café` (U+00E9) → the comparison
succeeds → verdict `clean`. This eliminates the NFD false-positive on macOS APFS where the
filesystem stores filenames in NFD but the link was typed in NFC.
- **Test:** `test_BC_2_07_003_nfc_eliminates_nfd_false_positive()`

### AC-011 (traces to BC-2.07.003 invariant 1)
`path_resolver` NEVER calls `std::path::Path::exists()` as the final match decision. All
matching is done against `DirIndex` entries (NFC-normalized name comparison). `Path::exists()`
would silently delegate to APFS case-folding on macOS, violating DI-002.
- **Test:** `test_BC_2_07_003_no_path_exists_call_in_resolver()` (confirmed by: `path_resolver.rs`
  has no `Path::exists` or `fs::metadata` import; unit test uses synthetic DirIndex only)

### AC-012 (traces to BC-2.07.003 invariant 2)
NFC normalization is applied to BOTH sides of every comparison: the link destination AND each
directory entry name from `DirIndex`. Normalizing only one side would miss NFD/NFC mismatches
in the other direction.
- **Test:** `test_BC_2_07_003_nfc_applied_both_sides_bidirectional()` (VP-009 proptest also
  covers idempotency; this is the directional coverage test)

### AC-013 (traces to BC-2.07.005 postcondition 1)
When a resolved path's `EntryKind` in `DirIndex` is `Dir` and the link has NO fragment,
the verdict is `clean`. A plain directory link `[x](docs/)` or `[x](docs)` where `docs`
is a directory is a valid navigation target.
- **Test:** `test_BC_2_07_005_plain_directory_link_no_fragment_is_clean()`

### AC-014 (traces to BC-2.07.005 postcondition 2)
When a resolved path's `EntryKind` in `DirIndex` is `Dir` and the link HAS a fragment
(e.g., `[x](docs#section)`), the verdict is `broken(target-is-directory)`. Anchor lookup
on a directory is impossible; `path_resolver` short-circuits without calling `anchor_resolver`.
- **Test:** `test_BC_2_07_005_directory_with_fragment_is_target_is_directory()`

### AC-015 (traces to BC-2.07.005 postcondition 3)
`anchor_resolver` is NEVER called when `path_resolver` determines the target is a directory
(with or without fragment). The routing decision stays entirely within `path_resolver`.
- **Test:** `test_BC_2_07_005_anchor_resolver_not_called_for_directory_target()` (verify via
  mock/callback: pass a spy `anchor_resolver` that panics if called; assert no panic)

### AC-016 (traces to BC-2.07.006 postcondition 1)
When a resolved path's `EntryKind` is `File` (or `Symlink { dangling: false }`) and the
file extension is NOT exactly `.md` (case-sensitive per D-012), the verdict is `clean`.
Extensions `.MD`, `.Md`, `.markdown`, `.mdx`, and any other non-`.md` extension fall into
this contract.
- **Test:** `test_BC_2_07_006_non_md_file_exists_verdict_clean()`

### AC-017 (traces to BC-2.07.006 postcondition 2)
The fragment (if present) is silently ignored for non-Markdown file targets. `[x](notes.txt#section)`
where `notes.txt` exists returns `clean` with no anchor lookup attempted.
- **Test:** `test_BC_2_07_006_fragment_on_non_md_file_ignored()`

### AC-018 (traces to BC-2.07.006 postcondition 3)
`anchor_resolver` is NEVER called for non-Markdown file targets. The routing decision is made
by `path_resolver` based on file extension alone, before any anchor resolution.
- **Test:** `test_BC_2_07_006_anchor_resolver_not_called_for_non_md_target()` (mock/spy pattern)

### AC-019 (traces to BC-2.07.006 postcondition 4)
When a non-Markdown file does NOT exist in `DirIndex`, verdict is `broken(file-not-found)`.
`[x](missing.py#L10)` where `missing.py` does not exist returns `broken(file-not-found)` —
the same reason code as for a missing `.md` file.
- **Test:** `test_BC_2_07_006_non_md_file_not_found_verdict()`

### AC-020 (traces to BC-2.07.008 postcondition 1)
A link destination with a trailing slash `[x](a.md/)` where the resolved base path `a.md`
exists as a regular file (`EntryKind::File`) returns `broken(file-not-found)`. The trailing
slash signals a directory path expectation; since `a.md` is a file not a directory, the path
`a.md/` does not resolve to any existing entry.
- **Test:** `test_BC_2_07_008_trailing_slash_on_file_is_file_not_found()`

### AC-021 (traces to BC-2.07.008 postcondition 4)
The reason code for trailing-slash-on-file is `file-not-found`, NOT `target-is-directory`.
`target-is-directory` applies only to the BC-2.07.005 case (a directory exists at the base
path AND a fragment is present). Here, no directory exists at `a.md/` — the path fails with
file-not-found. This distinction must be maintained to preserve correct downstream error messages.
- **Test:** `test_BC_2_07_008_trailing_slash_on_file_reason_is_file_not_found_not_target_is_directory()`
  (VP-024 proptest also verifies this invariant)

### AC-022 (traces to BC-2.07.008 invariant 1)
A trailing slash NEVER converts a file path into a `clean` result. Even if `a.md` exists and
is a regular file, `[x](a.md/)` is always `broken(file-not-found)` — never `clean`.
- **Test:** `test_BC_2_07_008_trailing_slash_never_clean()` (VP-024 proptest covers all
  inputs; this is the concrete regression test)

### AC-023 (traces to BC-2.07.008 invariant 3)
When `a.md` does NOT exist (neither as file nor directory), `[x](a.md/)` still returns
`broken(file-not-found)` — the same reason code, just for a different cause (ENOENT vs ENOTDIR).
- **Test:** `test_BC_2_07_008_trailing_slash_on_missing_file_also_file_not_found()`

### AC-024 (traces to BC-2.07.004 postcondition 2 — VP-004 P5 integration, D-165 discharge, gate #59)
**Integration test — path decode-ordering (P5):** A fixture `.md` file containing
`[x](./My%20File.md)` where `My File.md` exists on disk (file name contains a space) produces
a `clean` verdict. The path component `My%20File.md` is percent-decoded to `My File.md` by the
caller before passing to `path_resolver::resolve`, and the DirIndex lookup finds the decoded
entry. An implementation that passes the raw encoded string directly to the DirIndex lookup
produces `broken(file-not-found)`. This integration test falsifies decoder-omission in the
full pipeline and discharges the D-165 P5 obligation per gate #59.
**BINDING (D-165):** This test MUST remain an integration test — NOT converted to a Kani
proof. Operator gate #59 explicitly requires this obligation to stay as an integration test.
- **Test:** `test_vp004_p5_path_percent_decode_after_split()` in `integration_path_resolver.rs`

## Forbidden Dependencies

`crates/mdlinkcheck-core/src/path_resolver.rs` MUST NOT import:
- `std::fs` (any submodule)
- `std::process`
- Any network crate (`ureq`, `reqwest`, etc.)
- `anchor_resolver` (sibling module — ADR-001 decoupling)

If any of these appear in `path_resolver.rs`, the CI forbidden-dependency check MUST fail.
Enforcement: `grep -E 'use std::fs|std::process|anchor_resolver|ureq|reqwest' crates/mdlinkcheck-core/src/path_resolver.rs`
must return empty.
