# S-3.02: Anchor Table Construction — Three-Phase Pipeline and Heading/HTML Extraction

> **One-per-file:** This story is `S-3.02` in EPIC-03 — Anchor Checking (`E-3`).
> Implements `anchor_table.rs` (pure-core) and the three-phase pipeline ordering in `app.rs`
> (effectful-shell). Covers the complete anchor table universe: ATX/setext headings (slugged
> via S-3.01's `slug` module), HTML `id=`/`name=` attributes, and the Pass 1 → Pass 1.5 →
> Pass 2 ordering invariant that is mdlinkcheck's solution to DI-008.

## Narrative

- **As a** link-checker user
- **I want** mdlinkcheck to build a complete anchor table for every `.md` file before resolving any anchor link
- **So that** forward heading references and cross-file anchor links are resolved correctly — no false `anchor-not-found` verdicts caused by processing order

### AC-001 (traces to BC-2.05.001 postcondition 1)
After Pass 1 completes, every `.md` file reachable by the WalkBuilder traversal (including
files excluded as link sources by `--ignore` — DI-006 case 1) has a complete entry in
AnchorIndex. The LinkMap contains all extracted links from scan-set files.
- **Test:** `test_BC_2_05_001_pass1_builds_anchor_index_for_all_traversed_files()`

### AC-002 (traces to BC-2.05.001 postcondition 2)
After Pass 1.5 (success case): every `.md` link destination that appeared in the LinkMap but
was ABSENT from AnchorIndex after Pass 1 (due to `.gitignore`, dot-directory, or outside-root
exclusion — DI-006 cases 2, 3, 4) AND that exists as a readable regular file has a complete
AnchorIndex entry. Pass 1.5 identifies these targets by AnchorIndex membership absence alone;
it does NOT re-check which exclusion mechanism excluded them.
- **Test:** `test_BC_2_05_001_pass15_builds_anchor_table_for_gitignored_md_targets()`
- **Test:** `test_BC_2_05_001_pass15_builds_anchor_table_for_dot_dir_md_targets()`
- **Test:** `test_BC_2_05_001_pass15_uses_anchor_index_membership_as_sole_gate()`

### AC-003 (traces to BC-2.05.001 postcondition 2b)
Pass 1.5 failure branch: if a `.md` link destination that is absent from AnchorIndex does NOT
exist as a regular file (missing, not a regular file, or unreadable), then NO AnchorIndex entry
is created, NO `IoError` is recorded, and NO diagnostic is emitted. Pass 2 subsequently
produces the ordinary `broken(file-not-found)`, `broken(broken-symlink)`, or
`broken(target-is-directory)` verdict for links pointing to it.
- **Test:** `test_BC_2_05_001_pass15_missing_target_no_anchor_no_io_error()`

### AC-004 (traces to BC-2.05.001 postcondition 4)
No link validation (no calls to `anchor_resolver::resolve` or `path_resolver::resolve`) occurs
during Pass 1 or Pass 1.5. Verdicts are produced only in Pass 2.
- **Test:** `test_BC_2_05_001_no_link_validation_in_pass1_or_pass15()`

### AC-005 (traces to BC-2.05.001 postcondition 5)
No anchor table construction (no calls to `anchor_table::build`) occurs during Pass 2. The
AnchorIndex is immutable from the start of Pass 2 through its completion.
- **Test:** `test_BC_2_05_001_no_anchor_building_in_pass2()`

### AC-006 (traces to BC-2.05.001 invariant 1)
A file's anchor table is always fully populated before any cross-file anchor link pointing to
that file is resolved. This holds for ALL files in the anchor-target universe, including
out-of-scan-set files covered by DI-006.
- **Test:** `test_BC_2_05_001_anchor_table_complete_before_cross_file_resolution()`

### AC-007 (traces to BC-2.05.001 invariant 2)
Pass 1 completes fully before Pass 1.5 begins; Pass 1.5 completes fully before Pass 2 begins.
The three phases do not interleave. An integration test must assert that the AnchorIndex snapshot
after Pass 1 is strictly a subset of the AnchorIndex snapshot after Pass 1.5.
- **Test:** `test_BC_2_05_001_phases_strictly_sequential_no_interleaving()`

### AC-008 (traces to BC-2.05.001 invariant 4, DI-006 case 2)
A `.md` file excluded by `.gitignore` that is a cross-file anchor target from an in-scan-set
file has its anchor table built during Pass 1.5 (identified by AnchorIndex absence after Pass 1).
Integration test: `gitignored.md` has `## Section`; `a.md` has `[x](gitignored.md#section)`;
run mdlinkcheck — verdict is `clean`.
- **Test:** `test_BC_2_05_001_di006_case2_gitignored_target_gets_anchor_table()`

### AC-009 (traces to BC-2.05.002 postcondition 1)
Every ATX heading (`Tag::Heading` with level 1–6) in a file produces exactly one anchor table
entry whose key is the slug computed by `slug::compute()` from the heading's rendered text.
- **Test:** `test_BC_2_05_002_atx_heading_produces_one_anchor_entry()`

### AC-010 (traces to BC-2.05.002 postcondition 2)
Every setext heading (underlined with `=` for H1 or `-` for H2) produces exactly one anchor
table entry with its slug. Setext headings use the same slug computation as ATX headings.
- **Test:** `test_BC_2_05_002_setext_heading_produces_one_anchor_entry()`

### AC-011 (traces to BC-2.05.002 postcondition 3)
Duplicate headings within the same file receive suffixed slugs per the BC-2.06.001/002
DuplicateCounter. `## Setup` appearing twice gets `"setup"` and `"setup-1"`.
- **Test:** `test_BC_2_05_002_duplicate_headings_get_suffixed_slugs()`

### AC-012 (traces to BC-2.05.002 postcondition 4)
ATX headings inside fenced code blocks are NOT added to the anchor table (BC-2.04.003). The
pulldown-cmark event stream does not emit `Tag::Heading` inside a `Tag::CodeBlock`; the
`anchor_table::build` function must never see headings from code blocks.
- **Test:** `test_BC_2_05_002_headings_inside_code_blocks_excluded()`

### AC-013 (traces to BC-2.05.003 postcondition 1)
`<a name="foo">` in inline HTML is recognized and adds `"foo"` to the anchor table verbatim.
- **Test:** `test_BC_2_05_003_a_name_added_verbatim()`

### AC-014 (traces to BC-2.05.003 postcondition 2)
`<div id="bar">` and `<span id="baz">` add `"bar"` and `"baz"` respectively. Any HTML element
with an `id=` attribute is recognized; the element tag name is irrelevant.
- **Test:** `test_BC_2_05_003_div_id_and_span_id_added_verbatim()`

### AC-015 (traces to BC-2.05.003 postcondition 3)
HTML `id=` and `name=` values are used verbatim — not slugged and not lowercased. An element
`<a name="TOP">` adds `"TOP"` to the anchor table, not `"top"`.
- **Test:** `test_BC_2_05_003_id_name_values_used_verbatim_no_case_fold()`

### AC-016 (traces to BC-2.05.003 postcondition 4)
An empty value `id=""` is NOT added to the anchor table. Similarly `name=""` is not added.
- **Test:** `test_BC_2_05_003_empty_id_value_not_added()`

### AC-017 (traces to BC-2.05.003 invariant 1)
Only `id=` attributes on any element and `name=` attributes on `<a>` elements are recognized.
Other attributes (e.g., `class=`, `href=`, `data-anchor=`) are ignored. HTML that
pulldown-cmark cannot parse as inline HTML yields no anchor entries from that element.
- **Test:** `test_BC_2_05_003_only_id_and_a_name_recognized()`
