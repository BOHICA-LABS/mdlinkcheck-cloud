## Narrative

- **As a** developer implementing link resolution in `mdlinkcheck`
- **I want** `fragment::split` to correctly split at the first unescaped `#` (never at `%23`),
  and the callers of `split` to percent-decode both the path component (before directory-entry
  lookup) and the fragment component (before anchor-table lookup)
- **So that** links like `[x](My%20File.md)` resolve to `My File.md`, `[x](a%20b.md#section)`
  correctly separates path `a b.md` from fragment `section`, and `[x](path%23file.md)` treats
  the `%23` as a literal `#` in the filename rather than a fragment separator

### AC-001 (traces to BC-2.07.001 invariant 1)
`fragment::split(raw_dest)` splits at the first literal `#` character (ASCII 0x23). The
returned path component contains everything before the first `#`; the fragment is `Some(s)` where
`s` is everything after the first `#`. If no literal `#` is present, fragment is `None`.
- **Test:** `test_BC_2_07_001_split_at_first_literal_hash()`

### AC-002 (traces to BC-2.07.001 invariant 1)
`fragment::split(raw_dest)` NEVER splits on `%23` (percent-encoded `#`, ASCII 0x25 0x32 0x33).
A destination containing `%23` but no literal `#` returns `(raw_dest, None)` — the entire
string is the path component with no fragment.
- **Test:** `test_BC_2_07_001_percent23_is_not_a_split_point()`

### AC-003 (traces to BC-2.07.004 postcondition 1)
Fragment split ALWAYS precedes percent-decode. `fragment::split` operates on the raw destination
string (before any decoding) and returns borrowed slices. No percent-decoding occurs inside
`split`. This implements DI-003: split-before-decode ordering.
- **Test:** `test_BC_2_07_004_split_precedes_decode_ordering()` (verified by Kani P4: path + `#` + frag == original raw string, proving no mutation during split)

### AC-004 (traces to BC-2.07.004 postcondition 2)
The path component returned by `fragment::split` is percent-decoded (by the caller) before
directory-entry comparison. `[x](My%20File.md)` — path component `My%20File.md` decoded to
`My File.md` — is looked up in `DirIndex` as `My File.md`, not as the encoded string.
- **Test:** `test_BC_2_07_004_path_component_decoded_before_dir_entry_comparison()`
  (unit: call decode on split path; assert decoded string matches expected filename)

### AC-005 (traces to BC-2.07.004 invariant 1)
`%23` in the path component decodes to a literal `#` character; it does NOT become a fragment
separator after the split. A destination `[x](path%23not-frag.md)` results in path component
`path%23not-frag.md`, which decodes to `path#not-frag.md` — a literal `#` in the filename.
No anchor lookup is performed for this link.
- **Test:** `test_BC_2_07_004_percent23_decodes_to_hash_in_path_not_fragment_separator()`

### AC-008 (traces to BC-2.07.004 invariant 3)
An invalid percent sequence in the path component (e.g., `%GG`) is passed through undecoded.
The path component is used as-is in directory-entry lookup, which produces `broken(file-not-found)`
because no directory entry matches the raw encoded string. No panic; no new reason code.
- **Test:** `test_BC_2_07_004_invalid_percent_seq_in_path_passthrough()`

### AC-009 (traces to BC-2.07.004 invariant 3)
An invalid percent sequence in the fragment (e.g., `#caf%GG`) is passed through undecoded.
The raw fragment `caf%GG` is used for anchor-table lookup, which produces `broken(anchor-not-found)`
because no slug matches the undecoded string. No panic; reason code is `anchor-not-found`
(from the 13-code closed set). No new reason code is introduced.
- **Test:** `test_BC_2_07_004_invalid_percent_seq_in_fragment_passthrough()`

### AC-010 (traces to BC-2.07.007 postcondition 1)
A link with an empty destination string (`[x]()`) is classified by `url_classifier::classify`
as `UrlKind::Malformed(_)`. The verdict is `broken`, reason code `malformed-url`.
- **Test:** `test_BC_2_07_007_empty_dest_classified_malformed()`

### AC-011 (traces to BC-2.07.007 postcondition 2)
A link with a whitespace-only destination (`[x](   )`) — where pulldown-cmark trims leading/
trailing whitespace — produces an empty string after trimming and is classified as
`UrlKind::Malformed(_)`. Verdict: `broken(malformed-url)`. Not treated as a self-link.
- **Test:** `test_BC_2_07_007_whitespace_only_dest_classified_malformed()`

### AC-012 (traces to BC-2.07.007 invariant 1)
An empty destination is NEVER treated as a self-link (`[x](.)` or `[x](./#)`). It is distinct
from a same-directory reference. `url_classifier::classify("")` returns `Malformed(_)`, not
any path or fragment variant.
- **Test:** `test_BC_2_07_007_empty_is_not_self_link()`

### AC-013 (traces to BC-2.07.007 postcondition 4 — VP-023 proptest)
**Proptest:** For all arbitrary string inputs `s` where `s` is empty or whitespace-only,
`url_classifier::classify(s.trim())` returns `Malformed(_)`, NEVER `NonHttp`. This is the
VP-023 totality property ensuring no misclassification of empty destinations.
- **Test:** `proptest_vp023_url_classifier_totality_empty_dest()` (VP-023 proptest harness)

## Forbidden Dependencies

`fragment.rs` MUST NOT allocate (no `String`, no `Vec`) inside `split` — it returns borrowed
slices from the input. If `fragment::split` returns owned types, the Kani harness model size
explodes and the proof becomes infeasible. Enforce: `cargo clippy` lint `clippy::new_without_default`
and manual code review of return type.

`url_classifier.rs` MUST NOT call any I/O inside `classify`. `url::Url::parse()` is pure;
any future dependency on network or filesystem would invalidate the Kani-viability of the module.
