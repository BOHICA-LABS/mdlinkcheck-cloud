# S-7.01: Exit Code Determination — `verdict::exit_code`

> **One-per-file:** This story is `S-7.01` in EPIC-07 — Output, Reporting, and Exit Codes (`E-7`).
> Implements the pure-core `verdict.rs` module: the single function
> `verdict::exit_code(findings, io_errors, config_error) -> u8` that maps scan outcomes
> to POSIX exit codes 0, 1, and 2 with exit-2 priority. Kani-targetable (VP-005, VP-006).

## Narrative

- **As a** CI system or script consuming `mdlinkcheck`
- **I want to** receive predictable, unambiguous exit codes (0 = clean, 1 = broken links, 2 = error)
- **So that** I can gate deployments correctly: fail the pipeline when broken links are
  definitively found, fail differently when a scan error prevents a complete result,
  and never fail spuriously on transient or indeterminate conditions

## Behavioral Contracts

| BC | Title | Priority |
|----|-------|----------|
| BC-2.14.001 | Exit Code 0 — No Broken Links | P0 |
| BC-2.14.002 | Exit Code 2 Takes Precedence Over Exit Code 1 | P0 |
| BC-2.14.003 | Exit Code 1 — At Least One Broken Link Found | P0 |

## Acceptance Criteria

> **Verification Properties:** VP-005 (`vp-005-exit-code-io-error.md`, Kani, P0, DI-011)
> and VP-006 (`vp-006-exit-code-clean.md`, Kani, P0, DI-010) are the formal proofs for
> this story per VP-INDEX v1.7. Both are Kani harnesses that operate directly on the pure
> `verdict::exit_code` function.

### AC-001 (traces to BC-2.14.001 postcondition 1)
`verdict::exit_code(findings, io_errors, config_error)` returns `0u8` when `findings`
contains no entry with verdict `broken`, `io_errors` is an empty slice, and
`config_error` is `false`.
- **Test:** `test_BC_2_14_001_exit_0_all_clean()`

### AC-002 (traces to BC-2.14.001 postcondition 2 and invariant 2)
`verdict::exit_code` returns `0u8` when `findings` contains only `indeterminate` verdicts,
`io_errors` is empty, and `config_error` is `false`. Indeterminate findings never trigger
exit code 1 or 2.
- **Test:** `test_BC_2_14_001_exit_0_indeterminate_only()`

### AC-003 (traces to BC-2.14.001 invariant 3)
`verdict::exit_code` returns `0u8` when `findings` is empty (zero files scanned, e.g.,
an empty directory with no `.md` files), `io_errors` is empty, and `config_error` is `false`.
- **Test:** `test_BC_2_14_001_exit_0_no_findings_zero_files()`

### AC-004 (traces to BC-2.14.002 postcondition 1 and invariant 1)
`verdict::exit_code` returns `2u8` when `io_errors` is non-empty (at least one I/O error
recorded), regardless of whether `findings` contains broken verdicts. Exit 2 is strict —
no exception.
- **Test:** `test_BC_2_14_002_exit_2_io_error_beats_exit_1()`

### AC-005 (traces to BC-2.14.002 postcondition 1 and invariant 1)
`verdict::exit_code` returns `2u8` when `config_error` is `true` (sole trigger: an invalid
`--ignore` glob pattern detected by `globset` after clap parsing), regardless of whether
`findings` contains broken verdicts. Exit 2 is strict — no exception.
- **Test:** `test_BC_2_14_002_exit_2_config_error_beats_exit_1()`

### AC-006 (traces to BC-2.14.002 invariant 3 and BC-2.14.002 postcondition 2)
When `io_errors` is non-empty AND `findings` contains broken verdicts, `verdict::exit_code`
returns `2u8`. Both the broken findings and I/O errors are present in the output; no fail-fast
occurs (DD-007): the scan continues for all valid paths and broken links from successfully
scanned paths are still reported.
- **Test:** `test_BC_2_14_002_exit_2_both_broken_and_io_error()`

### AC-007 (traces to BC-2.14.003 postcondition 1)
`verdict::exit_code` returns `1u8` when at least one entry in `findings` has verdict
`broken`, `io_errors` is empty, and `config_error` is `false`.
- **Test:** `test_BC_2_14_003_exit_1_broken_link_no_io_errors()`

### AC-008 (traces to BC-2.14.003 invariant 1)
`verdict::exit_code` returns `0u8` (not `1u8`) when `findings` contains only `indeterminate`
entries and no `broken` entries, `io_errors` is empty, `config_error` is `false`. The
`indeterminate` verdict does NOT trigger exit 1.
- **Test:** `test_BC_2_14_003_indeterminate_does_not_trigger_exit_1()`

### AC-009 (traces to BC-2.14.002 invariant 3 — full precedence ordering)
The `verdict::exit_code` precedence is strictly enforced:
`io_errors non-empty OR config_error == true` → `2`;
else `any broken finding` → `1`;
else → `0`.
All six combinations of (has_broken, has_io_error, config_error) produce the correct result.
- **Test:** `test_BC_2_14_002_full_precedence_matrix()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-142 (id not authoritative — D-246; BC scenario: scan with 0 findings) | Directory scanned; no `.md` files found; `findings = []`, `io_errors = []`, `config_error = false` | Returns `0u8` — zero files is a valid "clean" result |
| EC-143 | Scan produces only indeterminate findings (e.g., `--online` mode with 429 responses) | Returns `0u8` — indeterminate does not raise exit code (BC-2.14.001 invariant 2) |
| EC-184 | Empty directory (no `.md` files at any depth) | Returns `0u8` (BC-2.14.001 invariant 3) |
| EC-169 | 1 broken link + invalid `--format` flag (config_error=true from cli validation) | Returns `2u8` — config_error=true via `--ignore` invalid glob path; note: invalid `--format` is handled by clap before app::run(), not via config_error |
| mixed-io | `mdlinkcheck good_dir/ nonexistent_dir/` — good_dir has 1 broken link; nonexistent_dir recorded as io_error | Returns `2u8`; broken finding from good_dir IS reported (no fail-fast, DD-007) |

**Note on EC-169:** `config_error = true` has exactly ONE trigger: an invalid `--ignore` glob
pattern detected by `globset` after clap parsing. Unrecognized CLI flags (e.g., `--format xml`)
are handled by clap before `app::run()` and do NOT set `config_error`.

## Forbidden Dependencies

`verdict.rs` MUST NOT import from `reporter`, `cli`, `main`, `scanner`, `http_client`, `app`,
`std::fs`, `std::net`, or `std::io`. If any of these appear in `verdict.rs`'s imports, the
build MUST fail (enforced by ADR-001 `cargo deny` rules and Kani harness compilation).
`verdict.rs` is a leaf module that depends only on `types`.
