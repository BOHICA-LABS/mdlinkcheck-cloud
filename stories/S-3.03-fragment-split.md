# S-3.03: Fragment Split at First Unescaped `#` Before Percent-Decode

> **One-per-file:** This story is `S-3.03` in EPIC-03 — Anchor Checking (`E-3`).
> Implements the `fragment` pure-core module in `mdlinkcheck-core`. This module is the
> gatekeeper for DI-003: the fragment is always split from the path at the first literal
> `#` character BEFORE any percent-decoding occurs. `%23` in a path is NOT a fragment
> separator — it is part of the path until percent-decoding converts it to `#`.

## Narrative

- **As a** link-checker user
- **I want** mdlinkcheck to correctly identify the fragment portion of any link destination
- **So that** `docs/a%23b.md` is treated as a path (no fragment) and `docs/a.md#section` correctly splits at the `#`

## Acceptance Criteria

> **Verification Properties (per VP-INDEX v1.7):**
> VP-004 (fragment split properties including `%23` trap T9 — Kani) and
> VP-013 (first `#` is split point — fuzz). Both referenced in frontmatter.

### AC-001 (traces to BC-2.08.003 postcondition 1)
When given a destination string containing a literal `#` (U+0023 that is NOT encoded as `%23`),
`fragment::split` scans left-to-right and splits at the first such `#`. Everything before it is
the path component; everything after it is the fragment.
- **Test:** `test_BC_2_08_003_split_at_first_literal_hash()`

### AC-002 (traces to BC-2.08.003 postcondition 2)
`fragment::split("docs/a.md#intro")` returns path `"docs/a.md"` and fragment `Some("intro")`.
- **Test:** `test_BC_2_08_003_canonical_split_example()`

### AC-003 (traces to BC-2.08.003 postcondition 3)
When there is no literal `#` in the destination string, there is no fragment. The entire string
is returned as the path component and fragment is `None`.
`fragment::split("docs/a.md")` returns path `"docs/a.md"` and fragment `None`.
- **Test:** `test_BC_2_08_003_no_hash_yields_no_fragment()`

### AC-004 (traces to BC-2.08.003 postcondition 4)
`%23` in the destination is NOT treated as a fragment separator. It is left as `%23` in the
path component; it becomes `#` only after percent-decoding (which happens after the split,
performed by the caller). `fragment::split("a%23b.md")` returns path `"a%23b.md"` and
fragment `None`.
- **Test:** `test_BC_2_08_003_percent23_not_a_fragment_separator()`

### AC-005 (traces to BC-2.08.003 invariant 1)
Fragment split ALWAYS precedes percent-decode (DI-003). The `fragment::split` function operates
on the raw (un-decoded) destination string and returns raw (un-decoded) components. Callers
percent-decode AFTER calling `fragment::split`. This ordering invariant is verified by the
VP-004 Kani harness.
- **Test:** `test_BC_2_08_003_split_operates_on_undecoded_string()`

### AC-006 (traces to BC-2.08.003 invariant 2–3)
The split point is the FIRST `#` in the string, not the last. Subsequent `#` characters after
the fragment start are part of the fragment, not additional split points.
`fragment::split("a.md##double")` returns path `"a.md"` and fragment `Some("#double")` (the
second `#` is part of the fragment, not a second split).
- **Test:** `test_BC_2_08_003_first_hash_is_split_point_not_last()`
- **Test:** `test_BC_2_08_003_subsequent_hashes_are_part_of_fragment()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-032 | `a%23b.md` | Path: `a%23b.md`; fragment: None. `%23` is NOT a split point. |
| EC-035 (id not authoritative — D-246) | `a%20b.md#section` | Path: `a%20b.md`; fragment: `Some("section")`. The `%20` is in the path; literal `#` splits normally. |
| EC-197 | `a.md##double-hash` | Path: `a.md`; fragment: `Some("#double-hash")`. First `#` splits; second `#` is in fragment. |
| (no EC) | `#` alone (anchor-only link) | Path: `""`; fragment: `Some("")`. Empty path, empty fragment. |
| (no EC) | `path.md#` (empty fragment) | Path: `"path.md"`; fragment: `Some("")`. Fragment string is empty (bare hash anchor — BC-2.08.001/002 both yield clean for this). |
| (no EC) | `%23only` (only percent-encoded hash, no literal hash) | Path: `"%23only"`; fragment: None. The whole string is path; `%23` is not a separator. |

> **D-246 note:** EC-035 is marked "id not authoritative" per operator ruling D-246. The
> BC scenario text (`a%20b.md#section`) is authoritative; the EC id points at an unrelated
> vector in the registry. Do NOT open `prd-supplements/test-vectors.md` to interpret EC-035.
