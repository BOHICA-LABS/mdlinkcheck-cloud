# S-2.01: Inline Link/Image Extraction with Kind Classification and Non-http Scheme Skipping

> **One-per-file:** This story is `S-2.01` in EPIC-02 — Link Extraction and Code Context Exclusion (`E-2`).
> Implements the core `link_extractor::extract` function that processes a `pulldown-cmark` event
> stream and returns `Vec<ExtractedLink>`. Covers inline links, image extraction (R3), CommonMark
> autolinks (BC-2.03.004), and non-http scheme clean-verdict skipping via `url_classifier`
> (BC-2.03.005). This story establishes the `link_extractor` module foundation that S-2.02 and
> S-2.03 extend.

## Narrative

- **As a** developer running `mdlinkcheck` on a Markdown repository
- **I want** inline links, image links, and CommonMark autolinks extracted from the parsed event
  stream with accurate source positions and kind classification
- **So that** downstream resolvers receive exactly the right set of link targets — relative-file,
  anchor-only, cross-file-anchor, external-http, or a silently skipped non-http(s) scheme — and
  no link receives more than one verdict

## Acceptance Criteria

> **Verification Properties:** VP-019 (`link_extractor` one-verdict proptest — DI-005: every
> unique `(dest, line, col)` tuple within a file produces exactly one `ExtractedLink`) and
> VP-014 (code-context exclusion integration test — DI-004: no link inside any code context is
> ever extracted; included because BC-2.03.001 invariant 1 cites DI-004) are referenced in
> frontmatter per VP-INDEX v1.7. BC-2.03.004 and BC-2.03.005 are test-sufficient per VP-INDEX
> v1.7 (no formal VP; covered by acceptance corpus).

### AC-001 (traces to BC-2.03.001 postcondition 1)
`link_extractor::extract(events)` returns one `ExtractedLink` for every `Tag::Link` and
`Tag::Image` event that occurs outside a code context in the pulldown-cmark event stream.
Events inside `Tag::CodeBlock` or `Event::Code` produce no `ExtractedLink`.
- **Test:** `test_BC_2_03_001_every_tag_link_outside_code_yields_one_extracted_link()`

### AC-002 (traces to BC-2.03.001 postcondition 2)
Each `ExtractedLink` carries: `source_file: PathBuf`, `line: usize`, `col: usize`,
`destination: String` (raw, unmodified destination string), and `link_kind: LinkKind`.
Line and column are derived from the byte offset of the `Tag::Link`/`Tag::Image` event via
the precomputed `link_line_map` in `ParsedFile`.
- **Test:** `test_BC_2_03_001_extracted_link_carries_source_file_line_col_dest_kind()`

### AC-003 (traces to BC-2.03.001 postcondition 3)
`link_kind` is determined solely from the destination string using these rules in order:
(1) destination starts with `http://` or `https://` → `LinkKind::ExternalHttp`;
(2) destination starts with `#` → `LinkKind::AnchorOnly`;
(3) destination contains `#` after at least one path character → `LinkKind::CrossFileAnchor`;
(4) all other destinations → `LinkKind::RelativeFile`.
- **Test:** `test_BC_2_03_001_link_kind_classification_rules_applied_in_order()`

### AC-004 (traces to BC-2.03.001 postcondition 4)
`Tag::Image` events are extracted and classified by `link_kind` identically to `Tag::Link`
events. An image with a missing target path (e.g., `![alt](missing.png)`) is extracted as
`LinkKind::RelativeFile` and yields a `broken(file-not-found)` verdict downstream.
- **Test:** `test_BC_2_03_001_image_tag_extracted_with_same_classification_as_link()`

### AC-005 (traces to BC-2.03.001 invariant 2)
`link_extractor::extract` never produces two `ExtractedLink` entries for the same
`(destination, line, col)` tuple within one file call. The proptest VP-019 property
`every_unique_dest_line_col_appears_exactly_once` holds for arbitrary valid Markdown input.
- **Test:** `test_BC_2_03_001_proptest_one_verdict_per_unique_dest_line_col()`
  (VP-019 proptest harness)

### AC-006 (traces to BC-2.03.004 postcondition 1)
`<https://x.com>` CommonMark autolinks (`LinkType::Autolink`) are extracted with
`link_kind: LinkKind::ExternalHttp`. In offline mode (default) the link receives a
`clean` verdict after `url_classifier` confirms the URL is syntactically valid.
- **Test:** `test_BC_2_03_004_angle_bracket_https_autolink_extracted_as_external_http()`

### AC-007 (traces to BC-2.03.004 postcondition 2)
`<mailto:user@example.com>` autolinks (`LinkType::Email`) are extracted with a destination
that begins with `mailto:` and are subsequently classified by `url_classifier` as a
non-http(s) scheme, receiving a `clean` verdict with no output emitted.
- **Test:** `test_BC_2_03_004_mailto_autolink_extracted_then_silently_skipped()`

### AC-008 (traces to BC-2.03.004 postcondition 3 and invariant 1)
`https://x.com` in plain prose without angle brackets produces zero `ExtractedLink` entries.
pulldown-cmark does not support GFM bare-URL autolinks (issue #494 per ADR-003 / DD-009).
This is verified for all possible prose contexts (paragraphs, list items, blockquotes).
- **Test:** `test_BC_2_03_004_bare_url_in_prose_produces_zero_extracted_links()`

### AC-009 (traces to BC-2.03.005 postcondition 1 and postcondition 2)
After `url_classifier::classify(dest)` returns a non-`ExternalHttp` non-`ExternalHttps`
`UrlKind` (e.g., `mailto:`, `ftp://`, `tel:`, `data:`, `vscode:`, `//host/path`), the link
is not submitted to any filesystem lookup or URL fetch, and it is not included in the text
or JSON output. The five non-http(s) variants EC-173 through EC-177 all produce exit 0 with
zero findings.
- **Test:** `test_BC_2_03_005_non_http_schemes_not_emitted_in_output()`

### AC-010 (traces to BC-2.03.005 postcondition 3)
The effective link verdict for any non-http(s) scheme link is `clean`. Non-http(s) links
never contribute to exit code 1.
- **Test:** `test_BC_2_03_005_non_http_scheme_verdict_is_clean()`

### AC-011 (traces to BC-2.03.005 invariant 1)
No diagnostic, warning, or informational message is emitted to stderr when a non-http(s)
scheme link is encountered. The skip is completely silent.
- **Test:** `test_BC_2_03_005_non_http_scheme_produces_no_stderr_output()`

### AC-012 (traces to BC-2.03.005 invariant 2)
`--allow <URL_PREFIX>` has no effect on non-http(s) scheme links. A link with destination
`mailto:user@example.com` remains `clean` whether or not `--allow mailto:` is supplied;
the `--allow` flag applies only to external http/https URL exemption.
- **Test:** `test_BC_2_03_005_allow_flag_has_no_effect_on_non_http_scheme_links()`

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-039 | `[x](logo.png)` — link with image-like PNG destination | Extracted as `LinkKind::RelativeFile`; receives file-not-found verdict if `logo.png` is absent |
| EC-040 | `![alt](missing.png)` — image with missing file | Extracted via `Tag::Image` as `LinkKind::RelativeFile`; verdict `broken(file-not-found)` |
| EC-113 | Link inside GFM table cell (e.g., `\| [x](a.md) \|`) | Extracted normally — pulldown-cmark emits `Tag::Link` inside `Tag::Table` events, which are not code contexts |
| EC-115 | Link inside blockquote or nested list | Extracted normally — pulldown-cmark emits `Tag::Link` inside `Tag::BlockQuote` or `Tag::List` events, which are not code contexts |
| EC-116 | `<https://example.com>` CommonMark angle-bracket autolink | Extracted as `external-http`; no findings in offline mode (syntax valid) |
| EC-117 | Bare `https://example.com` in prose without angle brackets | Zero `ExtractedLink` entries — GFM bare-URL autolinks are not supported per DD-009 |
| EC-173 | `[email](mailto:a@b.com)` | Non-http scheme — silently skipped; exit 0; no findings |
| EC-174 | `[ftp](ftp://x/y)` | Non-http scheme — silently skipped; exit 0; no findings |
| EC-175 | `[phone](tel:+15551234)` | Non-http scheme — silently skipped; exit 0; no findings |
| EC-176 | `[js](javascript:void(0))` | Non-http scheme — silently skipped; exit 0; no findings |
| EC-177 | `[proto-rel](//example.com/x)` | Protocol-relative URL — classified as non-http by `url_classifier`; silently skipped; exit 0; no findings |

## Architecture Compliance Rules (MANDATORY)

| Rule | Source | Enforcement |
|------|--------|-------------|
| `link_extractor` and `url_classifier` MUST NOT contain any I/O calls (`std::fs`, `std::net`, `std::io::stdout`, `std::time::Instant::now`, random-number generators) | ADR-001 (pure-core/effectful-shell boundary); purity-boundary-map.md §Boundary Rule | `cargo deny` rules + code review; Kani harnesses would become invalid if violated |
| `link_extractor::extract` MUST consume `&[OffsetEvent]` — the pulldown-cmark event stream with byte ranges from `into_offset_iter()`. It MUST NOT call `pulldown-cmark::Parser` directly (scanner owns parser construction) | ADR-003; module-decomposition.md §mdlinkcheck-core table (`link_extractor`: "Events pre-parsed by scanner") | Code review: confirm the function signature takes pre-parsed events, not a string |
| Link kind classification MUST use the destination string only — not file system state, not HTTP probing. Kind is a syntactic property of the destination | BC-2.03.001 postcondition 3; module-decomposition.md §Pure/Effectful Seam | Code review: `classify_kind(dest: &str) -> LinkKind` is a pure string operation with no I/O |
| Non-http(s) scheme classification is the responsibility of `url_classifier`, not an ad-hoc check inside `link_extractor`. The clean verdict for non-http(s) links flows through `url_classifier::classify` returning a non-Http/Https `UrlKind` | ADR-007 (three-verdict model); bc-module-map.md §SS-03 BC-2.03.005 ownership note | Code review: verify `link_extractor` does not duplicate the non-http detection logic |
| `pulldown-cmark` version MUST be exactly `0.13.4` as pinned in `Cargo.toml` | ADR-003; dependency-graph.md §mdlinkcheck-core table | `cargo verify` / `Cargo.lock` inspection |
| GFM bare-URL autolinks are permanently out of scope. No feature flag or extension may enable them | ADR-003 §Consequences (GFM bare-URL limitation); BC-2.03.004 invariant 1; DD-009 | Code review: confirm no `ENABLE_EXTENSIONS` or similar flag bypasses the pulldown-cmark limitation |
